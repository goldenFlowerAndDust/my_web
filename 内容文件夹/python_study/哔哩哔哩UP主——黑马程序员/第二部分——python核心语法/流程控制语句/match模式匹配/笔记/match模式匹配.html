match模式匹配

自行总结

  • 在JavaScript存在第二个条件分支语句， switch-case-default
  • python功能类似：match-case

  • 不同点

    1. JavaScript存在穿透效果，case必须由break结束

    2. 如：



      switch(要判断的变量){
        case 情况1:
          代码块
          break    // 因为有关键字 break 所以如果符合条件，执行完代码块，则退出switch
        case 情况2:
        case 情况3:
          代码块
          break    // 情况2与情况3之间没有关键字 break 所以它们共用一个代码块。
        ....
        default:    // 类似于 else 当所有条件均不满足时，执行内部代码块
          上述情况均不满足执行代码
      }
    3. 说到底，JavaScript必须由break退出，否则会一直穿透，直到最后，那样就没有任何意义了。
    4. JavaScript没有JavaScript的穿透效果，每个 case分支，都是退出条件，只要符合就退出match

    5. 如：



      match 需要判断的变量(如变量day):
        case 情况1:
          代码块    # 符合执行代码块，并退出match模式匹配
        case 情况2:    # 符合执行代码块(没有照样执行)，并退出match模式匹配，不会穿透到下一个case
        case 情况3 | 情况4:    # 【|】，match特有的，类似于逻辑或，多个条件满足一个即可
          代码块
    6. 所到底，pythoncase本身就是退出匹配关键字，不会由穿透效果，如果多个条件共享同一代码块，可以使用符号：【|】

    相同点

    1. 都是为了应对，同一个事件，多种状态的判断

    2. 如：


      match day:
        case 1:
          print("新的星期开始了")
        case 2 | 3 | 4:
          print("痛苦的上课")
        case 5:
          print("明天就休息了")
        case 6:
          print("愉快的休息")
        case 7:
          print("是个坏消息，明天要上课了")
    3. 可以看到，都是以day这个关键变量开始的。
pythonmatch-case VS JavaScript switch-case对照表
对比维度 pythonmatch-case JavaScriptswitch-case
匹配后行为 匹配成功后立即退match，不会执行下一个case 匹配成功后 继续穿透(fall-through),会执行后续case，知道遇到break
退出机制 case自带退出，无需额外关键字 必须手动写 break退出，否则会一直执行到switch结尾
多条件共享同一代码块
  • 使用 【|】组合：
  • 如：case "周六" | "周日":
  • 连续写 case(穿透)
  • 如：
      case "周六":
      case "周日":
        代码块
通配符(默认分支) case _:(相当于 else) default:(相当于 else)
是否支持结构匹配 ✅ 支持（可匹配列表、元组、字典等结构） ❌ 不支持（只能匹配值）
守卫条件（附加判断）
  • ✅ 支持 if：
  • case x if x > 0:
 ❌ 不支持
引入版本 Python 3.10（2021年） ES3（1999年，JavaScript 诞生初期）
设计哲学 匹配即退出，安全、显式、无副作用 默认穿透，灵活但容易出错，需人工 break

核心区别一句话总结
Python：匹配即退出，多个值用 | 组合；JavaScript：默认穿透，多个值靠连续 case 共享，必须用 break 阻止。
