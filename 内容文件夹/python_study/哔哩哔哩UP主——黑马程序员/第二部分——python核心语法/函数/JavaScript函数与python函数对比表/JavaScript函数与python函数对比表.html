JavaScript函数与python函数对比表

一、函数定义方式
对比维度 python JavaScript 核心差异
声明式定义 def 函数名(参数): function 函数名(参数){ } python用冒号 + 缩进，JavaScript用花括号
赋值式定义 函数名 = lambda 参数: 返回值(仅限单表达式) const 函数名 = function(参数){ } JavaScript支持完整函数体，python lambda只能写一行
匿名函数 lambda 参数: 返回值 function(参数) { }或(参数) => { } python lambda天生匿名，JavaScript匿名函数需要赋值给变量或作为回调函数使用
箭头函数(ES6) ❌ 无（lambda 是类似但功能受限） (参数) => {函数体} 箭头函数没有自己的this，lambda也没有self概念
类中方法 def 方法名(self,参数): 方法名(参数) { } python必须显式写self,JavaScript不用(但是在类中可用this)
内置函数 print()、len()、input()、max()、min()... console.log()、Math.max()、Array.map()... python内置函数在全局可用，JavaScript多在Math、Array等原型上

二、参数系统
对比维度 python JavaScript 核心差异
无参函数 def 函数名(): function 函数名() { } 写法相似，都是空括号
有参函数 def 函数名(a,b): function 函数名(a,b) { } 写法相似，形参在括号内
默认参数 def 函数名(a, b=10): function 函数名(a, b=10) { } ES6+支持默认参数，语法几乎一样
默认参数求值时机 定义时求值(def执行时) 调用时求值(每次调用重新计算) ⚠️ Python 默认参数是单例模式，可变对象有坑
关键字参数 ✅ 函数名(a=1, b=2) ❌ 不支持（只能传对象模拟） Python 独有，调用时可通过参数名传值
位置参数 函数名(1,2) 函数名(1,2) 两者都支持
不定长参数 *args(元组)、**kwargs(字典) arguments对象(类数组)或...rest(ES6真数组) JavaScript 的 ...rest 更接近 Python 的 *args
实参个数校验 ✅ 必须与形参个数匹配（默认参数除外） ❌ 实参可少于或多于形参，少的为 undefined，多的在 arguments 中 ⚠️ Python 更严格，JS 更灵活（但容易出错)

名词解释(python为主)：

  • 默认参数：定义函数时，给形参定义的默认值，后续会被调用传入的实参覆盖，若后续形参未传参，则使用默认值，并且一定在，非默认形参之后
  • 如：
    def num(a, b=10, c=20):
      print(a, b, c)
    num(10, 30) # 最后的结果是：10,30,20 因为没有给c 传实参，所以是默认值20

  • 关键字参数：

    • 调用函数时，直接给形参赋值。

    • 规则

      1. 关键字参数一定在位置参数后面，否则报错，语法错误：SyntaxError
      2. 传参顺序：先匹配位置参数，再匹配关键字参数(关键字参数顺序可以打乱，但与位置参数无关)
      3. 所以请确保：关键字参数的关键字，不与前面已被传参的形参重复，否则报错，运行错误：TypeError
      4. 最好解决办法：要么全部采用，关键字参数，要么定义函数的同时，将关键字形参放在最后面
  • 如：
    def num(a, b, c, d):
      print(a, b, c, d)
    num(10, 50, c=20, b=30) # 最后的结果是：10,30,20,50 ，# 看顺序，位置参数在前，关键字参数在后
  • 位置参数：调用函数时，根据传入的实参顺序，逐个按顺序给形参赋值,一一对应
  • 如：
    def num(a, b, c, d):
      print(a, b, c, d)
    num(10, 50, 20, 40) # 最后结果是：10, 50, 20, 40 实参与形参数量一致，且没有关键字参数干预，则实参赋值给形参顺序一一对应
  • 不定长参数：当形参中定义了 *args 或 **kwargs 时，多余的实参会被打包。
    python中*tuple[主要是运算符*]——打包元组,**dict[主要是运算符**]——打包字典
    JavaScript中arugments——类数组,...Array[主要是运算符...]——打包真数组

  • 所以

    • python中，当实参个数，多余形参个数，且形参没有定义：不定长参数，直接报错，
    • python，零容忍，实参超过形参个数
    • JavaScript则没那么多规矩，
        实参个数多余形参个数：则，多余的参数，放入对象：arguments
        实参个数少于形参个数，则，未被传参的形参，默认为undefined

三、返回值
对比维度 python JavaScript 核心差异
返回单个值 return 10 return 10 一样，可以返回任何数据类型
返回多个值 return 10,20——>自动打包成元组(10,20) 需要手动包成对象,return {a,b}或数组return [a,b]...任何数据类型 其实按真正返回多了值的概念，只有python，JavaScript本质返回一个容器，python同样能做到
无return关键字 默认返回：None 默认返回：undefined 语义不同但都是："空值"
return后面代码 不再执行 不再执行 一样
无返回值函数 常称“过程”（procedure），返回 None 常称“过程”，返回 undefined 语义相识
四、作用域与闭包
对比维度 python JavaScript 核心差异
函数作用域 ✅ 函数会生成新作用域 ✅ 函数会生成新作用域 一样
块级作用域 ❌ if、for 不生成新作用域 ✅ let/const 支持块级作用域 JavaScript更精细
全局变量读取 ✅ 直接读取外部变量 ✅ 直接读取外部变量 一样
修改全局变量 ⚠️ 需要 global 关键字 ✅ 直接修改（无需关键字） Python 更严格，必须显式声明
修改外层函数变量 ⚠️ 需要 nonlocal 关键字 ✅ 直接修改（闭包中) Python 更严格，必须显式声明
闭包 ✅ 支持（内部函数引用外部变量） ✅ 支持（内部函数引用外部变量） 概念一致，实现细节不同
变量提升 (Hoisting) ❌ 不存在，必须先定义后使用 ✅ var 声明的变量和函数声明会提升 Python 无提升概念，JS 有（易踩坑）

五、特殊函数类型
对比维度 python JavaScript 核心差异
递归函数 def func(): func() function func() { func() } 两者都支持，但 Python 有递归深度限制（默认 1000 层）
回调函数 ✅ 函数作为参数传递 ✅ 函数作为参数传递 概念一致，JS 更常见（事件监听、异步操作）
高阶函数 map、filter、reduce 等 map、filter、reduce 等 两者都支持函数式编程
生成器函数 yield 关键字 function* + yield 都有，语法略有差异
异步函数 async def + await async function + await 都有，Python 3.5+ 支持，JS ES8 支持

六、函数调用与 this / self
对比维度 python JavaScript 核心差异
实例方法中的 self / this ✅ 必须显式写 self 作为第一个参数 ❌ 隐式 this，无需在参数列表声明 Python 显式更清晰，JS 隐式更灵活（也更容易迷惑）
this 指向 ❌ 无 this 概念（用 self 代替） ✅ this 指向调用者，动态绑定 JS 的 this 是出了名的坑，Python 的 self 更直观
调用时传参 实例.方法(实参)（self 自动传入） 实例.方法(实参)（this 自动绑定） 调用方式相似
类方法 / 静态方法 @classmethod + cls / @staticmethod static 关键字（ES6+） 概念不同，Python 区分实例方法/类方法/静态方法

七、⚠️ 特别提醒（初学者最容易踩的坑）
陷阱 python JavaScript 说明
默认参数可变对象 ⚠️ 经典大坑！def func(lst=[]): 会累积数据 ✅ 每次调用重新求值，无此问题 Python 需用 None 来规避
修改外部变量 ⚠️ 必须 global / nonlocal ✅ 直接修改（闭包中） Python 初学者容易忘加关键字
实参数量不匹配 ⚠️ 报 TypeError ⚠️ 少传为 undefined，多传忽略或存 arguments Python 更严格，JS 更宽容（但容易产生隐蔽 bug）
闭包中的变量 ⚠️ nonlocal 声明后才能修改 ⚠️ 容易形成"循环引用"，注意内存泄漏 两者都有坑，但场景不同
递归深度限制 ⚠️ 默认 1000 层，超了报错 ⚠️ 浏览器引擎限制不同，但也会爆栈 大递归需手动优化或改用迭代

🎯 最终总结：Python 函数 vs JavaScript 函数
对比角度 一句话总结
函数定义 def + 缩进 vs function + 花括号（或箭头函数）
self / this Python 显式 self（清晰，不易出错）vs JS 隐式 this（灵活，容易迷惑）
作用域 Python 函数作用域 + LEGB 规则 vs JS 函数作用域 + 块级作用域（let/const）
参数系统 Python 严格匹配，支持关键字参数 vs JS 宽松匹配，支持 arguments / ...rest
返回值 Python 多值自动打包元组 vs JS 需手动打包对象/数组
变量提升 Python ❌ 必须先定义后使用 vs JS ✅ 函数声明和 var 会提升
综合评价 Python：严谨、统一、适合新手入门
JavaScript：灵活、多范式、但对新手不友好

  • 实参必须是：变量 = 值形式，最后打包，变量为键，值为字典的值
 字典

  • 概述

    以下为编程中常见的特殊函数类型，涵盖 Python 与 JavaScript 中的对应实现。

  • 类型 定义 特征 作用 示例
    递归函数 函数在其定义中调用自身
    • 必须设置终止条件（基线条件）
    • 每次调用会创建新的栈帧
    • Python 默认递归深度 1000
    		 解决可分解为相同子问题的问题（如树遍历、阶乘、斐波那契） def fac(n):
      return 1 if n <= 1 else n * fac(n-1)
    回调函数 作为参数传递给另一个函数，并在特定时机被调用
    • 编码者定义，由其他函数触发执行
    • 常用于异步或事件驱动场景
    • 形参固定，实参由调用方注入
    		 实现依赖反转，让调用方决定具体行为（如事件监听、数组遍历） btn.onclick = function() {
      console.log('点击了');
    };
    高阶函数 接收一个或多个函数作为参数，或返回一个函数
    • 以函数为一等公民的语言特性
    • 典型代表：map、filter、reduce
    		 将行为作为数据传递，实现函数组合与抽象 arr.map(x => x * 2) —— 将每个元素映射为原值的2倍
    匿名函数（Lambda） 没有函数名的简短函数定义
    • 单表达式，不能写多条语句
    • Python: lambda；JS: 箭头函数 () => {}
    • 通常作为临时回调或高阶函数的参数
    		 快速定义一次性逻辑，避免额外命名函数 sorted(list, key=lambda x: x['age'])
    —— 按年龄排序
    闭包（Closure） 内部函数引用了外部函数的变量，且外部函数已执行完毕
    • 内部函数“记住”了外部作用域的变量
    • Python 修改外部变量需 nonlocal
    • 常用于工厂函数、装饰器
    		 创建私有变量，实现数据封装与状态保持 def counter():
      count = 0
      def inner():
        nonlocal count
        count += 1
        return count
      return inner
    生成器函数 使用 yield 关键字逐步产生值的函数
    • 惰性求值：每次调用 next() 才执行
    • Python: def func(): yield ...
    • JS: function* func() { yield ... }
    		 处理大数据流或无限序列，节省内存 def gen():
      for i in range(3):
        yield i
    异步函数 使用 async / await 进行非阻塞操作
    • Python: async def func(): await ...
    • JS: async function func() { await ... }
    • 返回 Promise 或 协程对象
    		 在IO密集型任务中提高并发效率，不阻塞主线程 async def fetch():
      data = await get_data()
      return data
