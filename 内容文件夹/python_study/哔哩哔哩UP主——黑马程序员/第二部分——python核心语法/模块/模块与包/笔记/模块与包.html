模块介绍

什么是模块

  • 引入：当一个项目需要计算面积、周长，当其他文件内有计算结构的函数(方法)，我不想再写一次，想直接拿过来复用怎么办
  • 模块定义：python模块(module):一个.py文件就是一个模块，模块是python程序的基本组织单位。
  • 在模块中可以定义变量、函数、类，以及可执行的代码
  • 模块用法：将其他文件内的数据，导入到当前文件，实现多个文件数据共享。
  • 主要是实现：主程序与功能分离，提高代码质量，减少代码冗余。

使用模块需要的注意事项

  • 命名：与字面量的命名规则一致：硬性规则：不能以数字开头、只能包含：A-Z、a-z、非数字开头数字、下划线、中文(不建议用，虽然不会报错、但是运行可能会出BUG)
  • 模块的存储位置必须与导入模块为兄弟(同一个文件夹内)，否则获取不到
  • 模块识别顺序
  • 因为系统模块是最后查找的，所以自定义模块不能与系统自带模块重名，自定义模块会覆盖系统模块，导致功能出问题

导入模块

  • 导入模块：import关键字
  • 语法1：import 模块名
  • 直接导入整个模块，模块内的所有方法、类、变量...都存在模块名这个对象中，使用方式模块名.需要的功能
  • 语法2：from 模块名 import [方法、类、变量....]
  • 显示指定导入，可以一次多个导入，中间用逗号分隔

  • 通配符导入，初学者不容易分辨

    • 语法3：from 模块名 import *
    • 通配符导入，受制于被导入文件的：__all__ = [需要导入的功能]
    • 需要的功能可以是：变量、函数、类...
    • 与语法1和语法2不同，它导入的模块内如果有：__all__ = [需要导入的功能]，导入时只会导入指定的功能
    • 如果被导入文件，写法是__all__ = []空列表，则不会导入任何字面量
    • 如果被导入文件，没有__all__的同时使用通配符导入，则导入所有非下划线开头的字面量
    • 所以非常不建议用，语法1和语法2，将所有需要的内容放入一个命名的袋子，要想使用就必须：袋子名.需要的功能 重根本上就杜绝了，污染全局字面量的可能
    • 正常项目中，使用通配符导入的字面量，如果导入文件重名，会被导入文件覆盖，而且不会报错，完全是定时炸弹
    • 综上所述：应该避免使用
  • 可以使用as关键字重命名，后面使用模块的时候，就用重命名，否则默认模块名字
  • 语法：import math as shuxue
  • 这样的话，模块名字就变成了，shuxue，往后使用就用新的名字，但是注意：功能与原模块一致，且不会更改原模块名字，只能作用于当前文件。

包机制

  • 所谓的包就是：将多个模块封装成一个文件夹，这个文件夹就叫包
  • 主要作用是：使模块不那么碎片话，整理
  • 在 Python 中，一个文件夹若要被视为常规包，通常需要包含 __init__.py 文件（内容可以为空），它的作用是告诉Python ‘这是一个包’。虽然 Python 3.3+ 支持没有 __init__.py 的命名空间包，但在考试和常规项目中，建议始终保留 __init__.py 以确保兼容性和清晰性。
  • 包名可以是任何字符只要内部有：__init__.py文件即可，但是同样建议：使用字面量命名规则：A-Z，a-z，非数字开头数字，下划线，中文(正常项目同样不建议采用)
  • 默认包必须与主程序(导入它的文件)为兄弟关系，必须在同一个文件夹下。即使是兄弟子文件夹内都是不行
  • 后续可以使用：sys.path(中文名叫模块搜索路径)进行在所有文件夹下进行查询

导入包

  • 语法1[导入包和模块]：from 包名 import 模块
  • 语法2[导入包和模块的同时选择需要导入的内容]：from 包名.模块 import 内容

  • 通配符导入包，初学者容易出错

    • 语法3[通配符导入]：from 包名 import *
    • 注意导入的不是所有包内的模块，而是导入：__init__.py文件内，__all__ = [需要导入的模块]的模块，如果导入[]外的模块，尽管模块存在，同样报错
    • 如果：__init__.py文件中 __all__ = []，[]是空列表，则什么都不会导入，且不会报错
    • 如果：__init__.py文件中没有__all__，且使用通配符导入，则导入所有非下划线开头的模块
    • 使用这种方法，也可以，对比模块的导入，不会污染全局字面量，但是为未写__all__,几乎一次导入所有模块，看情况写

    导入包的模块采用通配符导入

    • from 包.模块 import *
    • 与单纯的：from 模块 import *行为一致，污染全局字面量，应避免使用
  • 内容可以是：类、变量、函数...，可以多个导入，之间用英文逗号隔开

模块识别顺序

使用sys模块，使包/模块在任何文件被访问

  • 介绍模块：sys:本质是 python进程启动时初始化的内存列表
  • 使用它其中一个功能，就能实现包/模块任何地方被找到：先导入：import sys，然后再使用：sys.path(中文名叫模块搜索路径).append(r'包的父目录')
  • 实现上面这两个操作后，就能正常导入：from 包名 import 模块/ import 模块....在IDE上，需要先写全，IDE才会识别
  • 整个过程：就是使用模块sys其中 sys.path(中文名叫模块搜索路径).append()方法， 为python插入一个锚点，让python在查询包的同时，在添加的锚点也查询一遍，实现任何地方都能使用包内的模块
  • 只有在控制台，sys才会执行，离开控制台，便会消失
    sys的存活周期：运行文件(生命开始)————过程——————结束运行(或终止运行)【声明周期结束】
    • sys.path[0]————>sys.path[1:]————>sys.path[-1]——————均找不到会报错
    • sys.path[0]:当前执行脚本所在的目录(默认自动加入)
    • sys.path[1:]:环境变量PYTHONPATH或手动 append、inset、extend添加的路径
    • sys.path[-1]:系统标准库路径(最后查找)
    • 所有位置搜索均没有，模块，则报错，显示未定义

其他模块知识

  • 调试：if __name__ == "__main__":

    1. __name__python内置的变量,表示当前模块的名字
    2. 定义：直接运行当前模块：__name__ 的值为 "__main__"
    3. 当导入模块时：__name__ 的值就是模块名字
    4. 总结就是：只有当该文件被直接运行时，__name__ 的值才会等于 "__main__"，该块内的代码才执行。 如果被导入，__name__ 的值是模块名，该块内的代码跳过不执行
    5. 用处1(被导入模块测试)：可以使用条件分支语句，指定需要运行的代码。( 前提是它上面没有运行的代码【提示：函数只有被调用才会执行】。)
    6. 用处2（被导入模块的安全防护）：将被导入模块中的测试代码或顶层调用放入 if __name__ == "__main__": 中， 确保模块被导入时不会意外执行这些代码，避免干扰导入方。
  • __init__在包中叫包名初始化(告诉：python这是一个包)、在类中叫构造函数：def __init__(self)

  • __all__

    1. __all__ = [需要导入的功能] 用来显式声明，当用户使用 from math import *时，默认导入哪些名称
    2. 当：__all__ = []为列表为空的时候，则什么都不会导入
    3. 当：没有 __all__的同时，使用通配符导入，则导入所有非下划线开头字面量/模块
    4. __all__ 只在 from 模块 import * 或 from 包 import * 时生效，普通import 和 from ... import 具体名称 不受影响。

  • pycharm新建文件时，用 / 构建层级路径

    1. / 前面的路径视为文件夹（若不存在则自动创建，支持多层嵌套）
    2. / 最后一段是实际创建的内容（文件或文件夹）
    3. 注意：只有路径的最后一段可以是文件；文件不能作为“容器”继续往下嵌套。
    4. 说白了：路径中，只有最后一个“节点”可以是文件，前面的所有“节点”都必须是文件夹（如果不存在则自动创建）。一旦某个节点是文件，它后面就不能再跟 / 了。
  • 常量：不会产生变化的量，写法规范是字母全部大写，如：PI = 3.1414926

方向规则
  • 只能从锚点开始，往'内层'走(用.分隔)
  • from 包.子包 import 模块
  • 不支持：../或./
  • 既可以往内，也可以往外（用 / 或 ../）。
  • ✅ ./style.css（当前目录）
  • ✅ ../style.css（上级目录）
  • ✅ /style.css（根目录）。
分隔符 点好(.)，表示"进入下一层命名空间" 斜杠(/)，表示"进入下一层文件夹"
能否用../ ❌ 绝对不行，这是语法错误。 ✅ 可以，../ 表示“回到上一层文件夹”。
能否用./ ❌ 不行，Python 导入不支持这个写法。 ✅ 可以，./ 表示“当前文件夹”。
能不能写完整物理路径 ❌ 不能写 C:/my_project/utils.py，只能写逻辑路径 utils。 ✅ 可以写完整 URL 或相对路径。

因为有正常开发有IDE，可以在IDE设置源根，然后从源根向内点到包或模块，说白了就是将从源根开始，包嵌套包结构，源根也是包，from 包.子包.子子包... import *

  • 在一些强大的IDE中使用：pycharm、VScode...

    1. 因为：sys.path是运行当中，才会正确添加，这会导致，pyCharm的检查出问题：比如：错误提示、使用模块不会提示模块内的变量、类、函数等。
    2. 所以，正常开发，将包的父文件夹设置为源根，或更上面设为源根，最后通过源根点到包名即可，这样 pycharm不会报错，提示功能正常使用

  • 在一些比较基础的开放环境中使用：IDLE...

    1. 这类开发环境有一个共同特点：无法设置源根
    2. 方法一：老方法：import sys+sys.path
    3. 坏处：每个文件都要导入
    4. 方法二：修改环境变量：在系统变量查找PYTHONPATH(如果没有自己创建一个)，添加需要导入包的绝对地址即可
    5. 查找环境变量设置：此电脑右键单击属性——找到高级系统设置——单击环境变量——知道系统变量——新建或双击PYTHONPATH然后添加即可
