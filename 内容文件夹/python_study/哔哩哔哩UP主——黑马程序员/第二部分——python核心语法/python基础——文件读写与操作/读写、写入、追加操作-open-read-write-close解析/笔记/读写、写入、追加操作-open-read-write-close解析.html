读写、写入、追加操作-open-read-write-close解析

回顾读模式

  • 只读文本：r,rt、读取原始二进制：b,rb
  • 共同特点：当文件不存在或路径写错，会报错：FileNotFoundError

open()、read()、write()、close()

  • open()

    1. 主要作用：返回一个'文件对象'(File Object)
    2. 可以理解为：链接到这个文件的遥控器/管道

    3. 内含

      • 文件在操作系统中的 句柄[也叫编号]
      • 当前的读写位置(光标/指针)
      • 以及编码着指定的：编码规则(encoding)和读写模式(读、写、追加)

  • read()

    1. 主要作用：只读取文件对象所指文件内容
    2. 语法：字面量 = 文件对象.read()
    3. 扩展：只可以传一个参数，指向的文档开头开始，读取与参数相同数量的字符
    4. 所以：参数必须是整数，如果是浮点数或字符串，会报错：TypeError
    5. 如果参数为负数，读取整个文件内容，等价于：文件对象.read()

  • write()

    1. 主要作用：可以写入操作
    2. 语法：字面量 = 文件对象.write('内容')
    3. 扩展：只可以传一个参数，具体内容
    4. 具体内容有什么限制由：mode决定
    5. 如果写入的数据与 mode不匹配，则会报错，TypeError

  • close()

    1. 主要作用：关闭文件、销毁文件对象，释放资源
    2. 语法：字面量 = 文件对象.close()
    3. 注意：不能传参
    4. 如果传参则报错：TypeError,原因：操作数类型不匹配

读写（r+、rb+、rt+）

  • r+：可读可写，文件必须存在，光标在开头，写入时会覆盖原有内容
  • 模式：r+、rb+
  • 语法：open(文件地址,mode='模式',encoding='解码器')
  • 注意：先读后写，所以 文件必须真是存在，否则报错：FileNotFoundError

  • 运行过程

    1. r+/rb+/rt+ 打开文件时，光标位于文件开头。写入时从光标位置开始覆盖（写几个字符就覆盖几个字符），不会自动清空原文件。读取操作会从当前光标位置开始读取。
    2. r+/rt+写入必须是字符串、rb+写入必须是：二进制。不会自动将Unicode字符转为bytes
    3. 不懂二进制要想写入二进制可以采用：b'字符串'的形式，自动转为二进制写入

写入（w、wt、wb）

  • 文本写入模式：w、wt
  • 文本写入，所以：write()必须是字符串，否则报错：TypeError
  • 二进制写入：wb
  • 二进制写入，所以：write()必须是二进制,否则报错：TypeError

  • 共同特点

    1. 文件不存在，自动创建。
    2. 清空原文件内容，新内容覆盖
  • w等价于wt
  • 注意：文本写入/二进制写入，write()，传参是字符串/二进制

追加（a、at、ab）

  • 文本追加模式：a、at
  • 文本写入，所以：write()必须是字符串，否则报错：TypeError
  • 二进制写入：ab
  • 二进制写入，所以：write()必须是二进制,否则报错：TypeError

  • 共同特点

    1. 文件不存在，自动创建。
    2. 保留原文件内容，且指针在文件在最后面，新内容在指针后面追加
  • a等价于at
  • 注意：文本写入/二进制写入，write()，传参是字符串/二进制

读写 (w+、wt+、wb+、a+、at+、ab+)

  • 顾名思义：可读可写
  • w:覆盖写入、a：结尾追加、t：字符串、b：二进制，概念完全相同
  • 注意：w是覆盖写入，打开文件，内容就已经清空了、如果确实需要读，必须先 write() 写入新数据，再 seek(0) 才能读到。直接 read() 读到的永远是空字符串。
  • 注意：a是追加写入，打开文件，内容就存在，但是光标在结尾、要想读取，需要将光标移动至最前面。使用方法：seek(0,0)，写的时候又要重新将光标移动至最后，seek(0,2) tell()
  • 注意：与 r+、rb+、rt+ 不同，w+、wt+、wb+、a+、at+、ab+ 在文件不存在时不会报错(FileNotFoundError)，而是新建文件。
  • 所以除非有特殊目的，最好还是读写分开

建议

  • open()——打开、read()——读取、write()——写、close()——关闭是文件处理的方法、是本质。
  • r、b、rt、rb、w、wt、wb、a、at、ab是open()内的：mode的值 控制的是模式。只读、读写、写入、追加
  • open返回的是文件对象，包含模式
  • read返回的是文件内容，只要是提取内容都需要它
  • write没有返回值，只要是写入内容都需要它
  • close没有返回值，每个文件打开，必须要关闭，避免浪费资源、避免内容泄露损失
  • 注意：r、rt、rb、b模式打开的文件，只能读：read()、readlines()，使用：write()、writelines() 会报错(io.UnsupportedOperation： not writeable)
  • 注意：w、wt、wb、a、at、ab模式打开的文件，只能写：write()、writelines()，使用：read()、readlines() 会报错(io.UnsupportedOperation： not readable)
  • 注意：r+、rb+、w+、wt+、wb+、a+、at+、ab+模式打开的文件，可读可写：write()、writelines()、read()、readlines()、 不会报错(io.UnsupportedOperation： not readable(或not writeable))
学习顺序 分类 内容 说明 示例
1. 前置基础 编码基础 str 字符串类型，本质是 Unicode 编码的二进制 name = 'YLH'
bytes 字节类型，本质是 utf-8/gbk 等编码的二进制（对 Unicode 压缩） data = name.encode('utf-8')
编码转换 encode() 将 Unicode 按指定编码（返回 bytes） data = name.encode('utf-8')
编码转换 decode() 将其他编码转回 Unicode（返回 str） result = data.decode('utf-8')
2. 路径规则 绝对路径 从盘符或根目录开始的完整路径 好处：一步到位；坏处：文件移动后路径失效，不适合部署 C:/Users/info.txt
相对路径 基于当前脚本所在目录的路径 好处：项目移动后依然有效；坏处：脚本运行目录变化时基准改变 ./data/file.txt
3. 路径符号 ./ 当前目录（同级） 可直接写文件名，省略 ./ ./info.txt
../ 上级目录 可多次使用，如 ../../ ../data/info.txt
文件夹名/ 进入下一级文件夹 相当于 ./文件夹名/ data/info.txt
4. 核心方法 open() 返回 文件对象（“遥控器/管道”） 内含：句柄、读写位置、编码规则、模式 open('info.txt', mode='r', encoding='utf-8')
read() 读取文件内容 只传 1 个参数（整数/负数）；负数等价于读取全部 data = file.read(10)
write() 写入内容 只传 1 个参数；内容类型由 mode 决定 file.write('hello')
close() 关闭文件，释放资源 不能传参；否则 TypeError file.close()
5. 模式分类 只读模式 r（等价于 rt）
rb		 文件不存在 → FileNotFoundError open('info.txt', 'r')
写入模式 w（等价于 wt）
wb		 文件不存在自动创建，清空原内容再写 open('info.txt', 'w')
追加模式 a（等价于 at）
ab		 文件不存在自动创建，光标在末尾，追加新内容 open('info.txt', 'a')
读写模式 r+（文本）
rb+（二进制）		 文件必须存在，光标在开头，写几个覆盖几个 open('info.txt', 'r+')
6. 编码注意事项 默认编码 open() 默认编码与操作系统挂钩 Windows: GBK，Linux/macOS: utf-8 open('info.txt')
编码规则 文件编码 ≠ 系统默认编码时，必须显式指定 encoding 否则抛出 UnicodeDecodeError open('info.txt', encoding='utf-8')
编码写法 utf-8 等价于 UTF-8 等价于 uTf-8 建议统一写法，不要混用 encoding='utf-8'
7. 异常处理 FileNotFoundError 文件路径不存在或输入错误 只读/读写模式（r / r+）下抛出 open('不存在的文件.txt', 'r')
UnicodeDecodeError 读取时编码不匹配（解码失败） 通常发生在 Windows 读 UTF-8 文件时未指定 encoding open('utf-8文件.txt', 'r')（Windows）
TypeError 操作数的“类型”不对 数量错误（如 read(10, 20)）
类型错误（如 1 + 'abc'）		 open('info.txt', mode=123)
ValueError 类型对了，但“值”不对 如 int('abc') → 类型对了（字符串），但值不合法 int('abc')
8. 最佳实践 显式指定 encoding 无论什么系统，都显式指定 encoding='utf-8' 保证代码跨平台运行一致 open('info.txt', 'r', encoding='utf-8')

扩展——异常类型：TypeError 和 ValueError

  • TypeError

    1. TypeError: '操作数'的类型本身不匹配（类型错误）
    2. 操作数：传参的实参、运算符号两边的字符
    3. 类型：可以是运算时数据类型错误、传参时数据类型错误、传参数量错误

    4. 比如

      open("info.txt", mode=123)， 这里面mode必须是字符串，类型错误，所以：TypeError

  • ValueError

    1. ValueError: '操作数'的类型本身匹配（类型错误），但是结果/值错误
    2. 操作数：传参的实参、运算符号两边的字符
    3. 类型：可以是运算时数据类型错误、传参时数据类型错误、传参数量错误

    4. 比如

      int('abc')，int()方法支持传字符串，但是实参是非数字字符串，值错误，所以：ValueError
