魔法方法

  • 定义：魔法方法是指python中提供的双下划线开头和结尾的特殊方法。
  • 作用：用于定义类的特殊行为,比如：__init__
  • 特殊：魔法方法不需要手动调用，python会在合适的时机自动调用
  • 时机：看下面的表格

  • python的魔法方法速查表

    一、基类(base class)————所有已知对象的雏形

    基类（object）

    • object 是 Python 中所有类的“老祖宗”，所有类（包括 int、str、list 和你的自建类）都直接或间接继承自它。
    • 它提供了所有对象最基本的行为，比如：
      • __new__：分配内存，创建空白实例
      • __init__：初始化实例属性（默认不做任何事）
      • __str__、__repr__：返回对象的字符串表示
    • 你写的每一个类，即使不写 class Student(object)，也默认继承自 object。
    • 所以，数字、字符串、列表、函数、自建类……它们都是这个“基准”的派生品，都能用 __new__ 创建，也都能用 __str__ 转换成字符串，只是默认实现是返回内存地址而已。

    • 将多个对象，通过运算符行为，重新组合成一个对象
    • 定义 @运算符的行为
    • @：矩阵乘法(较少用)
    		 执行：对象1 @ 对象2
    注意
    • 只能是两个参数，运算符左边的：self，运算符右边的：other
    • 以上运算法则同样：同级运算符：从左到右(除了特殊情况：括号、加减与乘除混合)
    • 当(加减与乘除混合)：优先计算乘除，再进行加减,有括号除外

    • 但是计算过程可以是多个对象：比如：object1 + object2 + object3

      1. 同级运算：从左往右计算
      2. 第一步：object1(self) + object2(other) = total(结果)——这个total就是临时对象，第一个调用：__del__
      3. 第二步：total(结果——在左边[slef]) + object3 = total2
      4. 可以看到：从始至终都只有两个参数：(self/other)
      5. 计算的结果取决于运算符的左边还是右边，左边则为：slef，右边则为：other
      6. 比如：object1 * object2 + object3 / object4
      7. 先计算(乘除)：(object1 * object2= result2) 和 object3 / object4 = result1
      8. 加号左边的是：result1也就是self，右边的是：result2也就是other
      9. 所以最后结果也是：self + other,两个参数
      10. 减法/乘法/除法同样的道理，同级从左往右

    • 总结：

      1. 固定两个参数，但是可以多个参数参与计算，每次计算的结果按符号位置，左边为：self，右边为：other
      2. 魔法方法本身，不受同级运算和混合运算影响，但是计算过程受：python解释器影响(正常数学运算)。
      3. 运算参数必须是数字，可以指定需要执行运算的部分
      4. 在链式运算中：中间过程会产生临时变量，这个临时对象一旦后续没有操作会被立刻回收: 调用：__del__
      5. 所以执行(__del__)的顺序是：临时对象——原始对象——输出结果后
      6. 返回的是结果
      7. 最后严格遵守：官方硬性规定(必须遵守), 社区最佳实践(强烈遵守)

    比较方法——(等于、大于等于、小于等于、小于、大于)
    __eq__(self,other)

    • 定义 <运算符的行为

    		 执行：对象1 < 对象2
    __le__(self,other)
    • 将多个对象，通过运算符行为，返回一个布尔值

    • 定义 <=运算符的行为
    • 记忆：lt:less than equal。less——小，than——比较，equal——相等取首尾单词首字母
    		 执行：对象1 <= 对象2
    __gt__(self,other)
    • 将多个对象，通过运算符行为，返回一个布尔值
    • 具体返回值，由编码者决定，但非常不建议，返回除布尔值以外所有类型
    • 定义 >运算符的行为
    • 记忆：lt:greater than。greater——大，than——比较取首字母
    		 执行：对象1 > 对象2
    __ge__(self,other)
    • 将多个对象，通过运算符行为，返回一个布尔值
    • 具体返回值，由编码者决定，但非常不建议，返回除布尔值以外所有类型
    • 定义 >=运算符的行为
    • 记忆：lt:greater than equal。greater——大，than——比较，equal——相等取首尾单词首字母
    		 执行：对象1 >= 对象2
    注意
    • 与运算方法一致，只能有两个参数，运算符左边的是：self，右边的是：other

    • 所采用的形式均是链式比较：比如：a == b == c == d

      • 所谓的链式比较：均是拆分操作，先拆分，然后默认使用: and相连
      • 比如案例：a == b == c ===> a==b and b==c and c==d
      • 多个对象进行比较，最后都会默认由：and连接
      • 再比如：a > b > c > d ===> a>b and b>c and c>d
      • 回顾：and与or
        1. 它们均有短路系统
        2. and：返回第一个False（那么后续代码短路，不会进行判断），若均没有返回最后一个：True
        3. or：返回第一个True(那么后续代码短路，不会进行判断)，若均没有返回最后一个：False

    • 总结

      1. 链式比较：拆分、然后由and连接，然后得出最后结果
      2. 拆分过程就是，运行比较方法的过程，从来都是两两比较，左边：self，右边：other
      3. 最后返回的结果是布尔值
    主要体现在：实例对象直接引用是内存地址，不能进行比较、计算。可以通过运算符重载魔法方法，自定计算、比较规则

扩展——属性/方法查询与模块查询之间的关系

  • 属性/方法查询

    1. 已知：int、float、str、容器、函数、自建类都是基于，基类(base class)衍生出的子类，也就是它们都有共同的父类——基类(object)
    2. 已知：__dict__是每个对象、类中必会存在、用于存储当前对象的属性/方法
    3. 也是正是因为每个对象、类中都有自身独立的：__dict__，所以不会互相影响，这就是封装
    4. 实例对象通过：先通过：__dict__内查询属性/方法，再通过：__class__查询对应类的__dict__
    5. 子类通过：__bases__，查询父类的：__dict__
    6. 所以查询顺序：实例对象本身(__dict__)————>
      通过接口__class__查询对应类(__dict__——————>
      通过接口__bases__查询父类(__dict__)———————>
      直到查询到基类(object)未找到——————>报错
    7. 从下往上查询：__dict__，对象与类接口是：__class__，子类与父类接口是：__bases__
    8. 子类与父类的关系就是继承关系，子类继承父类的所有属性和方法。通过：super()方法，使用父类的属性和方法
    9. 因为每个对象/类都有自己独立的：__dict__，更改的操作只会修改自身的：__dict__，所以同名方法可以有多种不同的效果，这就是多态
    10. 魔法方法就是继承基类的属性和方法的结果，可以自行修改，自建类定义的同名方法(魔法方法)覆盖原本基类的效果(修改自身：__dict__)，所以基类原本方法不受影响，本质也是多态的延申

  • 模块查询

    1. 当前文件夹(sys.path[0])——————> 源根(sys.path[1,-1])——————> python自带模块(sys.path[-1])——————>报错
    2. 从下往上查询，以sys.pathpython运行列表为主

  • 相同点与不同点

    1. 相同点：

      • 查找顺序都是从下往上查找
      • 均找不到，则报错

    2. 不同点：

      • 属性/方法是以：__class__、__bases__引用对应的地址(接口)找到对应的__dict__内查询
      • 模块是以：sys.path的顺序查找
      • 属性/方法查询的尽头是：基类(object)，模块查询的尽头是：语言自带的模块

官方硬性规定(必须遵守)

  • 必须返回 NotImplemented，而非抛出异常：当你的魔法方法不支持某个操作（例如，学生
    + 字典）时，必须返回 NotImplemented 这个特殊值。这让 Python
    有机会去尝试调用右侧对象的反向方法（如 __radd__）。如果直接抛出
    NotImplementedError，程序会直接崩溃，而不会给右侧对象任何机会。
  • 方法应返回新对象：对于 __add__、__sub__ 这类运算，通常应该返回一个运算结果的新对象，而不是修改 self 或 other。这能避免产生难以预料的副作用

  • 不能改变的规则：运算符重载有一些不可逾越的限制

    1. 不能改变运算符的优先级（例如，让 + 比 * 先算）
    2. 不能改变运算符的结合性（例如，让 - 从右向左结合）
    3. 不能改变运算符的元数（例如，让 + 变成三目运算符）
    4. 不能创建新的运算符（例如，不能发明一个 ~~ 运算符）

社区最佳实践(强烈遵守)

  • 保持语义清晰（避免滥用）：这是最重要的一条原则。重载一个运算符，必须让它做的事情符合人们对这个运算符的普遍认知。

    1. ✅ 好的例子：让 + 实现向量的加法，让 * 实现金额的乘法。语义明确，一看就懂。
    2. ❌ 坏的例子：让 * 实现“复制用户”的功能。这不符合乘法的直觉，会让人困惑，应该用 user.duplicate() 这样的普通方法。

  • 保持一致性：实现比较运算符时，要保持逻辑上的一致。

    1. 如果你实现了 __eq__，通常也应该实现 __hash__，这样才能保证对象能正常放入集合或作为字典的键。
    2. 如果你实现了 __lt__，最好把 __gt__、__le__、__ge__ 等也一并实现，或者使用 functools.total_ordering 装饰器来补全。
  • 避免副作用：魔法方法不应该修改操作数的状态（除非是 __iadd__ 这样的原地运算）。同时，魔法方法内部也不应该包含复杂的 I/O 操作或日志记录，它应该只专注于实现运算逻辑。
  • 善用类型检查：在方法内部，可以使用 isinstance() 来检查 other 的类型。如果不是期望的类型，应返回 NotImplemented，让 Python 去尝试反向运算。
  • 实现完整协议：不要只实现单个魔法方法，而应考虑实现一整套相关的协议。例如，让一个类支持迭代，就应该实现 __iter__ 和 __next__，而不是只实现一个 __getitem__。

  • 反向方法（__radd__）与就地方法（__iadd__）

    1. 当你实现 __add__ 时，通常也应该考虑实现其“反向”版本 __radd__， 以支持操作数顺序交换的情况（如 3 + 学生）。
      同时，+= 这样的增强赋值运算符，是由 __iadd__ 方法实现的。如果没有定义 __iadd__，Python 会回退到使用 __add__。
