## 2. Python · 语法基石

### 2.1 标识符（三级规范模型）

| 层级 | 内容 | 违反后果 |
|---|---|---|
| **硬性规定** | 字母/数字/下划线，不以数字开头，非关键字，区分大小写 | `SyntaxError` |
| **PEP 8 行规** | 变量/函数 `snake_case`；类 `PascalCase`；常量 `CONSTANT_CASE`；私有 `_prefix` | 不报错，损害协作 |
| **个人建议** | 不用中文、见名知意 | — |

**关键顿悟**：`class = 1` 报 `SyntaxError` 而不是运行时错误 —— 因为关键字是**词法层**的硬约束，在解释器构建 AST 阶段就失败，`try-except` 永远追不上它。这条认知在异常处理章节被反复强化，属于真正的"底层理解"。

### 2.2 变量与动态类型

```python
a, b = 10, 20
a, b = b, a          # 本质：右侧先组包成元组，再解包赋值
```
你把它拆成"**先组包 `t=(b,a)`，再解包 `a,b = t`**"，并进一步推出"交换无需中间变量"的底层机制 —— 这是从"会用"到"懂为什么"的分水岭。

### 2.3 输出格式化三阶演进

```python
"..." + str(age) + "..."        # ① 拼接：需手动 str()，Python 无隐式转换
"%s" % (name, age)              # ② 占位符：可读性提升
f"{name} {age:.2f}"             # ③ f-string：支持表达式、方法调用、格式说明符
```

**格式说明符** `{value:.2f}`、`{value:>10}`、`{value:^10}`（中文占 2 个显示宽度）—— 这条在后续所有表格对齐打印中被高频使用。

## 3. Python · 运算符：真值体系与三个语言的分歧点

### 3.1 整除与取余 —— 全库最硬核的一块推导

| 表达式 | Python | JS / MySQL | 根因 |
|---|---|---|---|
| `5 // 3` | `1` | `1` | — |
| `-5 // 2` | `-3` | `-2` | Python **向下取整**，JS **向零取整** |
| `-5 % 3` | `1` | `-2` | 余数符号**跟随除数**（Python） / **跟随被除数**（JS） |
| `5 % -3` | `-1` | `2` | 同上 |

**底层公式**（笔记中完整的推导链）：
```
余数 = 被除数 - 除数 × 商
其中"商"取整方式决定了余数符号的归属
```

> **洞察**：你没有停留在"记住结论"，而是把 `//`、`%`、`divmod` 统一在**同一个数学恒等式**下。这是可迁移的思维方式——找到一个不变量，让所有特例变成推论。

### 3.2 真值 / 假值（Falsy 清单）

```python
False, None, 0, 0.0, 0j, "", [], (), {}, set()
```
JS 侧：`false, null, undefined, "", 0, -0, NaN`

**关键差异**：`[] == false` 在 JS 为 `true`（隐式转换），在 Python 为 `False`（无隐式转换）。这解释了后续"`if result:` 判空"在两种语言中完全不同的风险等级。

### 3.3 `and` / `or` 返回操作数而非布尔值

```python
0 and 5     # → 0     （第一个假值）
2 and 3     # → 3     （全真，返回最后一个）
0 or 5      # → 5     （第一个真值）
2 or 3      # → 2     （全真，返回第一个）
```
**推论**：`x = a or default` 是 Python 惯用法；而 `if a and b` 的判断流是"返回值 → 再判真假 → 再分支"，这个两段式模型被你明确写出。

### 3.4 `is` vs `==`（身份 vs 相等）

```python
a = [1,2]; b = [1,2]
a == b    # True   值相等（调用 __eq__）
a is b    # False  地址不同
x is None # 推荐：None 是单例，is 更安全（不受 __eq__ 重写欺骗）
```

### 3.5 位运算符的"双重身份"

| 运算符 | 整数（二进制） | 集合（集合运算） |
|---|---|---|
| `&` | 按位与 | 交集 |
| `\|` | 按位或 | 并集 |
| `^` | 按位异或 | 对称差集 |
| `~` | 按位取反（`~x == -x - 1`） | ❌ 不支持 |
| `& ~` | — | 差集（集合专用） |

**你已跳出"位运算=底层技巧"的刻板印象**，明确指出它在集合场景下就是"语法糖形式的集合 API"，同时保留了 `1 << n`（造位）、`x >> n`（拆包）、`& 0xFF`（消毒）三种真实工程用途。

## 4. Python · 流程控制

### 4.1 三套分支的定位

| 结构 | 适用 | 特性 |
|---|---|---|
| `if / elif / else` | 区间判断、条件组合 | Python 分支**不创建作用域**（与 JS 的 `let` 块级作用域不同） |
| `match / case` | 离散值枚举、结构匹配 | **无穿透**、`\|` 多值合并、`case x if 守卫` |
| 三元表达式 | 单表达式二选一 | `值1 if 条件 else 值2`（注意顺序与 JS 相反） |

**`match` 与 `switch` 的 5 个差异**（笔记中对比清晰）：
1. JS 需 `break` 防穿透；Python 天然不穿透
2. 多值合并：JS 用"连续 case 落空"；Python 用 `|`
3. Python 支持守卫 `case x if x > 0:`
4. Python 支持结构匹配（解构字典/序列）
5. Python `case _` 是通配；JS `default` 是兜底

### 4.2 循环的"唯一形式"

**Python 只有 `for-in` 一种 for 循环**，变化只在于"迭代对象"：
```python
for item in container:      # 元素
for i in range(n):          # 索引（range = 左闭右开，步长 ≠ 0）
for i, v in enumerate(c):   # 索引 + 元素
for k, v in d.items():      # 键值对（解包）
for a, b in zip(x, y):      # 拉链
```

**`for-else` / `while-else`**：else 在"**未被 break 正常结束**"时执行 —— 这是 Python 独有的"未打断"语义，等价于 `for..else { flag }` 的 JS 模式。

### 4.3 图形打印（嵌套循环的思维体操）

已实现的图案工程：
- 空心矩形 / 实心矩形
- 等腰三角形（`2*i-1` 星号 + `(2n-1-2i+1)//2` 空格）
- 菱形：`stars = 2 * min(i, n-1-i) + 1` ← **用绝对值/最小值函数消掉"上半 + 下半"的分支**
- 九九乘法表、国际象棋棋盘格（`(i+j)%2` 决定 emoji）

> **洞察**：菱形用 `min(i, n-1-i)` 这一个小技巧，把"两次循环 + 两次 if"压缩为一次循环 —— 这是从"能画出来"到"找到对称轴"的抽象跃迁。

## 5. Python · 数据容器（本库最扎实的一块）

### 5.1 五容器的四维分类

| 容器 | 有序 | 可重复 | 可变 | 元素约束 | 底层 |
|---|---|---|---|---|---|
| `list` | ✅ | ✅ | ✅ | 任意 | 动态数组 |
| `tuple` | ✅ | ✅ | ❌ | 任意 | 定长数组 |
| `str` | ✅ | ✅ | ❌ | 仅字符 | 不可变字节序列 |
| `set` | ❌ | ❌ | ✅ | 可哈希 | 哈希表 |
| `dict` | ✅(插入序) | 键❌ 值✅ | ✅ | **键可哈希** | 哈希表 |

### 5.2 切片三步骤模型（自建推导，含金量极高）

```
① 归一化：负索引 → 正索引（正向 = len + 反向）
② 判空： 正向 < 反向 且 步长 > 0  → 有交集
         正向 > 反向 且 步长 < 0  → 有交集
         越界部分直接裁剪到有效边界
③ 取值： 沿步长方向，左闭右开，取到结束索引前一个
```

**配套结论**：
- 切片取值越界 → 返回空列表，**不报错**
- 切片赋值越界 → `IndexError: cannot assign to a slice that is completely out of bounds`（因为赋值要在"不存在的位置"插入）
- 切片赋值长度 ≠ 原切片长度 → 原列表**长度会变化**（先删后插）
- 步长为 `0` → `ValueError`

> **洞察**：`切片取值` 与 `切片赋值` 的错误行为不对称，这在全库中被单独点出。这是"读"和"写"语义差异的典型案例，很多人用了三年 Python 都没注意到。

### 5.3 解包（Packing / Unpacking）的两侧语义

**左侧 `*`（收集）**：
```python
x, *y, z = [1,2,3,4,5]   # x=1, y=[2,3,4], z=5
```
分配规则（笔记已总结为口诀）：
> **先分配 `*` 外的变量，`*` 再收剩余；以 `*` 为界，左取左、右取右。**

**右侧 `*`（展开）**：
```python
[*list1, *list2]         # 合并，返回新列表，不改原容器
{*set1, *set2}           # 合并去重
{**d1, **d2}             # 合并字典（后者覆盖）
f(*args, **kwargs)       # 拆开传参
```

**约束**：一次解包中 `*` 至多一个；函数形参中 `*` 至多一个、`**` 至多一个且在最后。

### 5.4 推导式家族

| 类型 | 语法 | 求值 | 内存 |
|---|---|---|---|
| 列表 | `[expr for x in it if cond]` | 急 | 大 |
| 集合 | `{expr for x in it if cond}` | 急 | 中（去重） |
| 字典 | `{k_expr: v_expr for x in it if cond}` | 急 | 大 |
| 生成器 | `(expr for x in it if cond)` | **惰** | 极小（单元素） |
| 元组 | ❌ 不存在，用 `tuple(gen)` 强转 | — | — |

**去重三法（笔记已给出选型决策）**：
```python
list(set(data))               # 顺序不重要 → 最快
list(dict.fromkeys(data))     # 顺序重要 → 保序去重
for x in data: if x not in seen: ...   # 教学 / 自定义逻辑
```

### 5.5 字典的本质

**哈希键 = 值的身份证**：`hash(key)` 定位桶，`key` 必须是不可变（`str/int/float/tuple/bool/None`），`list/set/dict` 不可作为键。

**三种视图**：`keys()`、`values()`、`items()` 返回**动态视图**（原字典变化，视图实时更新），可迭代但**不可下标**。

**常用方法矩阵**：
```python
d.get(k, default)      # 安全查，不存在返回 default（不报错）
d.setdefault(k, dv)    # 不存在则插入并返回 dv
d.pop(k)               # 返回值，键不存在报 KeyError
d.popitem()            # 3.7+ 弹出最后一项，返回 (k, v)
d.update(other)        # 合并，同键覆盖
dict.fromkeys(it, v)   # 批量造键（注意：value 若为可变对象会共享引用！）
```

## 6. Python · 函数（本库第二大强项）

### 6.1 参数矩阵（含优先级）

```
位置参数 > 默认参数 > *args > 强制关键字参数 > **kwargs
```

**合法 / 非法签名速查**：

| 签名 | 合法性 | 说明 |
|---|---|---|
| `def f(a, *b)` | ✅ | — |
| `def f(a, **b)` | ✅ | — |
| `def f(a, *b, **c)` | ✅ | 经典组合 |
| `def f(a, *, b, **c)` | ✅ | `*` 后为强制关键字 |
| `def f(a, *b, *c)` | ❌ | 两个 `*` 冲突 |
| `def f(a, **b, *c)` | ❌ | 顺序反了 |
| `def f(a=1, b)` | ❌ | 默认参数必须在后 |

**传参冲突矩阵**：
```python
num(10, 30, b=50, c=10)   # TypeError：b 已被位置实参占用
num(10, d=30, 30)         # SyntaxError：位置实参不能在关键字实参之后
```

### 6.2 作用域（LEGB）

```
Local → Enclosing → Global → Built-in
```
- 读全局：无需关键字
- **改**全局：`global x`
- 改外层函数变量：`nonlocal x`
- 不加关键字直接赋值 → **创建新的局部变量**（不是修改外层）—— 这是最容易踩的坑

**查找链的扩展（面向对象阶段）**：
```
属性：实例 __dict__ → __class__.__dict__ → __bases__.__dict__ → ... → object
方法：从 __class__ 开始（实例 __dict__ 不存方法）
```

### 6.3 递归（含栈帧可视化）

**三段式模型**（自建）：

```
递归 = 入栈挂起 + 出栈计算 + 逐层传递
```

- 基线条件：`n == 1` 或 `n <= 10` → 返回非自身
- 递推式：`n * f(n-1)` / `n % 10 + f(n//10)`
- Python 默认深度 **1000**（`sys.getrecursionlimit()`）
- 尾递归**不优化** → 深递归会 `RecursionError`

**亮点**：用 `sums(123) = 3 + sums(12)` 的逐层展开图，把"栈顶先返回、逐层出栈"这条抽象描述画成了具体的调用序列。

### 6.4 高阶函数与 lambda

| 函数 | 作用 | 返回值 | 是否改原容器 |
|---|---|---|---|
| `sorted(it, key=fn, reverse=)` | 排序 | **新列表** | ❌ |
| `list.sort(key=fn, reverse=)` | 排序 | `None` | ✅ |
| `map(fn, it)` | 映射 | 惰性迭代器 | ❌ |
| `filter(fn, it)` | 筛选 | 惰性迭代器 | ❌ |
| `functools.reduce` | 归约 | 标量 | ❌ |

**`key` 接收的是"函数对象"，不是"调用结果"** —— `key=len` ✅，`key=len()` ❌。这条在 `sorted(data_list, key=lambda x: len(x))` 中被明确点出。

**lambda 的三条边界**：
- 只能是**单表达式**（不能写 `if/for/try` 语句，但可写三元表达式）
- 无 `return`，表达式的值即返回值
- 天生匿名，需赋给变量或直接作为回调

### 6.5 文档字符串

```python
def circle_area(radius):
    """
    功能 : 计算圆面积 area = πr²
    约束 : 使用异常处理拦截非法输入
    :param radius: 半径
    :return: 数字返回面积，否则 None
    """
```
已形成 `:param:` / `:return:` 的标准 Sphinx 风格，`help(fn)` 或 IDE 悬浮可直接查看 —— **这是团队协作级别的好习惯**。

### 6.6 类型注解（含容器泛型）

```python
name: str = "YLH"
ids: list[int]
mapping: dict[str | int, float]
pair: tuple[int, str]              # 下标级标注
var_len: tuple[int, ...]           # ... 表示"后续元素同类型"
def f(*args: int, **kwargs: int) -> tuple[list[str], list[int]]: ...
```

**关键边界**：
- 注解**只是提示**，不强制校验，赋值不报错（除非用 `mypy`/`pydantic`）
- `...` **只能**用于 `tuple`，且必须在最后且只出现一次
- `Any` 表示"放弃类型检查"
- `str | int`（3.10+）等价于 `Union[str, int]`
- 注解**不支持解包赋值**：`a, b: int = 1, 2` 语法错误

## 7. Python · 异常处理体系

### 7.1 语法全貌

```python
try:
    risky()
except ValueError as e:
    handle(e)
except (TypeError, KeyError):
    ...
else:
    no_exception()
finally:
    cleanup()          # 无论是否异常都执行
```

### 7.2 异常层次树（已画出结构）

```
BaseException
├── SystemExit
├── KeyboardInterrupt
├── GeneratorExit
└── Exception                    ← 常规异常父类
    ├── StopIteration / ArithmeticError(ZeroDivisionError, OverflowError)
    ├── LookupError(IndexError, KeyError)
    ├── NameError(UnboundLocalError)
    ├── OSError(FileNotFoundError)
    ├── RuntimeError(RecursionError)
    ├── TypeError / ValueError
    └── SyntaxError(IndentationError)   ← 运行前抛出，except 抓不到
```

**三条硬结论**（笔记中反复强调）：
1. `SyntaxError` 及其子类发生在**编译期**，`try-except` 根本来不及执行
2. 裸 `except:` 会吞掉 `KeyboardInterrupt`（Ctrl+C 无法中断）—— 是反模式
3. 生产代码应 `except 具体类型` 或至少 `except Exception`，并在 `finally` 中**禁止 `return`**（会覆盖异常/返回值）

### 7.3 `raise` 的三种位置语义

| 位置 | 是否被捕获 | 后果 |
|---|---|---|
| `try` 内 | ✅ | 后续被 `except` 处理，程序继续 |
| `except` 内 | ❌（除非嵌套） | **立即中断**，常用于异常转译 `raise TypeError(...) from e` |
| `try` 外 | ❌ | 立即中断 |

**`raise NewError() from old_error`**：保留原始异常的 `__cause__`，形成异常链，traceback 会打印"During handling of the above exception..."。

### 7.4 异常传递（栈模型）

```
内层函数抛异常 → 沿调用栈向上抛 → 中间层无捕获则继续向上 → 最外层仍无 → 程序终止，打印 traceback
```

**工程建议**（你已总结）：
- 小项目：每处独立 try
- 大项目：主流程统一兜底，减少冗余；但底层**不要吞异常**，要么处理要么让它冒泡

## 8. Python · 文件 I/O 与编码

### 8.1 模式矩阵

| 模式 | 读 | 写 | 文件不存在 | 光标初始 | 是否清空 |
|---|---|---|---|---|---|
| `r` / `rt` | ✅ | ❌ | `FileNotFoundError` | 0 | 否 |
| `rb` | ✅ | ❌ | `FileNotFoundError` | 0 | 否 |
| `w` / `wt` | ❌ | ✅ | **自动创建** | 0 | **✅ 清空** |
| `wb` | ❌ | ✅ | 自动创建 | 0 | ✅ 清空 |
| `a` / `at` | ❌ | ✅ | 自动创建 | 末尾 | 否 |
| `ab` | ❌ | ✅ | 自动创建 | 末尾 | 否 |
| `r+` | ✅ | ✅ | `FileNotFoundError` | 0 | 否（覆盖写） |
| `w+` | ✅ | ✅ | 自动创建 | 0 | ✅ 清空 → **读前必须 `seek(0)`** |
| `a+` | ✅ | ✅ | 自动创建 | 末尾 → **读前必须 `seek(0)`** | 否 |

**典型报错**：
- 用 `r` 模式 `write()` → `io.UnsupportedOperation: not writable`
- 用 `w` 模式 `read()` → `io.UnsupportedOperation: not readable`
- `w+` 打开后直接 `read()` → 读到 `""`（因为光标在开头但文件已被清空）

### 8.2 编码的本质

```
str  (Unicode 抽象字符)  --encode('utf-8')-->  bytes (硬盘/网络的二进制)
bytes                     --decode('utf-8')-->  str
```

- `open()` 的默认编码**跟随操作系统**：Windows = GBK，Linux/macOS = UTF-8
- 跨平台/跨机器项目：**必须显式 `encoding='utf-8'`**
- 编码不匹配 → `UnicodeDecodeError: 'gbk' codec can't decode byte ...`

### 8.3 光标 API

```python
f.seek(offset, whence)   # whence: 0=文件头 1=当前位置 2=文件尾
f.tell()                 # 返回当前字节偏移
```
- **文本模式下 `seek` 以"字节"为单位**，非 ASCII 字符（中文占 3 字节）中间跳转会导致解码错误
- 文本模式建议只用 `seek(0)` 或 `seek(0, 2)`
- `seek(offset, 1)` / `seek(offset, 2)` 在文本模式下受限制（`io.UnsupportedOperation`）

### 8.4 `with` 语句

```python
with open('data.txt', 'rt', encoding='utf-8') as f:
    content = f.read()
# 退出块自动 close()，即使中途抛异常
```
`with` = **上下文管理器协议**（`__enter__` / `__exit__`），本质是"保证资源释放"的语法糖。

### 8.5 读写的四个方法

| 方法 | 返回 | 备注 |
|---|---|---|
| `read(size)` | `str` / `bytes` | 不传或负数 = 读全部；只能传 int |
| `readline(size)` | `str` | 到末尾返回 `''`（**不是 None**） |
| `readlines()` | `list[str]` | 每行含 `\n` |
| `write(s)` | `int`（写入字符数） | 需手动加 `\n` |
| `writelines(it)` | `None` | **不自动加换行**；参数须为可迭代对象 |

## 9. Python · 模块与包

### 9.1 导入五式

```python
import math                          # math.sqrt()
import math as m                     # m.sqrt()
from math import sqrt, pi            # sqrt()
from math import sqrt as s           # s()
from math import *                   # ⚠️ 污染全局，受 __all__ 控制
```

### 9.2 `__all__` 的两种作用域

| 位置 | 作用 |
|---|---|
| **模块**（`.py`） | 控制 `from module import *` 时导入哪些**名称** |
| **包**（`__init__.py`） | 控制 `from package import *` 时导入哪些**子模块对象** |

- `__all__ = []` → 什么都不导入
- **没有** `__all__` → 导入所有非 `_` 开头的公有名称

### 9.3 `if __name__ == "__main__":`

```
直接运行该文件      → __name__ == "__main__" → 块内代码执行
被 import 到别处    → __name__ == "模块名"    → 块内代码跳过
```

**两个用途**：① 隔离模块自测代码 ② 保护顶层执行语句，防止被 import 时误跑。

### 9.4 包（Package）

- 目录 + `__init__.py`（Python 3.3+ 有命名空间包，但工程上仍建议保留）
- 默认只能导入**兄弟目录**下的包
- 跨目录：`sys.path.append(r'包的父目录')` 或设置 `PYTHONPATH`
- IDE（PyCharm）中把包父目录标为 **Sources Root**，可解决"导入不报红、自动补全"问题
- **重要差异**：模块用 `.` 逐层向内（`from 包.子包 import 模块`），**不支持 `./` 或 `../`**；而 HTML 路径支持相对外跳。两者不可混用。

## 10. Python · 面向对象（进行中）

### 10.1 三要素模型

```
类     = 蓝图 / 模板（定义属性 + 方法）
实例   = 按蓝图造出的具体对象
self   = 实例自身（方法第一个参数，调用时不传）
```

### 10.2 属性分类（四级）

| 类型 | 定义位置 | 存储 | 影响范围 |
|---|---|---|---|
| 实例属性 | `__init__` 中 `self.x = v`，或 `obj.x = v` | 实例 `__dict__` | 仅该实例 |
| 类属性 | 类体内、方法外，或 `ClassName.x = v` | 类 `__dict__` | 所有实例（读） |
| 局部变量 | 方法内非 `self.` 定义 | 栈帧 | 仅该方法 |
| 私有属性 | `self.__x` | 名称改写成 `_ClassName__x` | 语义私有 |

**关键陷阱**：`obj.类属性 = v` **不会**改类属性，而是在实例 `__dict__` 新建同名属性**遮蔽**掉类属性 —— 只有 `ClassName.类属性 = v` 才真正改类。

### 10.3 查找链（封装 / 继承 / 多态的底层统一）

```
属性:  实例.__dict__ → __class__.__dict__ → __bases__.__dict__ → ... → object.__dict__ → AttributeError
方法:  从 __class__ 起（实例 __dict__ 通常不存方法）
```

**三大特性都可以从这个链条推导出来**：
- **封装** = 每个对象拥有独立 `__dict__`，互不干扰
- **继承** = `__bases__` 让查找链向上延伸
- **多态** = 同名方法在各 `__dict__` 中独立存在，按 `__class__` 分派

### 10.4 魔法方法（已实践）

| 魔法方法 | 触发时机 | 关键约束 |
|---|---|---|
| `__new__(cls)` | 创建实例（最先） | 返回实例，默认 `object.__new__` |
| `__init__(self)` | 初始化（`__new__` 后） | 不负责创建，只加属性 |
| `__del__(self)` | 销毁前 | 不保证及时执行 |
| `__str__(self)` | `print()` / `str()` | **必须返回 str** |
| `__repr__(self)` | `repr()` / 交互式回显 | 面向开发者 |
| `__add__(self, other)` | `+` | 返回**新对象**，不支持时返 `NotImplemented` |
| `__eq__` / `__lt__` / `__gt__` ... | 比较运算 | 返回 bool，链式比较默认 and 连接 |
| `__hash__` | `hash()` | 重写 `__eq__` 后默认变 `None`，需补 |

**运算符重载四条铁律（已整理）**：
1. 不能改**优先级**
2. 不能改**结合性**
3. 不能改**元数**（`+` 永远是二目）
4. 不能**创造新运算符**
5. 类型不符必须返回 `NotImplemented`（不是抛异常）→ 让 Python 尝试 `__radd__`
6. 保持语义直觉（别让 `*` 表示"复制用户"）

### 10.5 三大特性 + 三种方法（高阶笔记已就位）

| 方法类型 | 装饰器 | 第一参数 | 可访问 | 调用 |
|---|---|---|---|---|
| 实例方法 | 无 | `self` | 实例 + 类 | `obj.m()` |
| 类方法 | `@classmethod` | `cls` | 类属性 / 其他类方法 | `Cls.m()` / `obj.m()` |
| 静态方法 | `@staticmethod` | 无 | 都不能（纯工具函数） | `Cls.m()` |

配套：`@property`（把方法伪装成属性，做读写控制）、`__slots__`（限定属性名，省内存）、`ABC`（抽象基类强制子类实现）。

## A 类 · 控制流陷阱（最隐蔽、影响最大）

### A1. `except` 块里没有 `return`，函数"带着错误继续跑"

**现象**（`异常处理.py`）：
```python
def judgment_number(a, b, c):
    try:
        int(a); float(b); int(float(c)); float(D)
    except ValueError:
        print("...")
        return None
    except NameError:
        print('包含未定义的变量')     # ← 没有 return！
    return a, b, c                  # ← 会继续执行到这里
```
调用 `judgment_number('50', 30, '15.6')` 时 `D` 未定义触发 `NameError`，函数打印警告后**仍然返回了 `('50', 30, '15.6')`**，调用方 `if result: print(result)` 照常输出。

**根因**：`except` 分支只是"普通代码块"，不是"函数出口"。异常被捕获只意味着"程序不崩溃"，不意味着"流程终止"。

**解法**：
```python
except NameError:
    print('包含未定义的变量')
    return None          # 显式终止
```

**延伸**：这是 `try-except` 最反直觉的一点——**捕获 ≠ 中断**。凡是 `except` 中声明"失败"的，都必须配 `return` / `raise`，否则后续代码会把失败当成功处理。同理 `finally` 中写 `return` 会**覆盖** `try` 的返回值或异常，是更严重的同类问题。

### A2. `break` 拼写成 `brea`（`random.py`）

**现象**：猜数字游戏末尾是 `brea`，运行时 `NameError: name 'brea' is not defined`，且循环无法退出。

**根因**：手误 / 编辑中断。但关键问题是：**它没有在开发阶段被发现**。

**解法**：
1. 立即修：`break`
2. 建立防线：`python -m py_compile file.py` 或 IDE 的语法高亮/静态检查（PyCharm 会直接标红）
3. 养成"**写完一个函数立刻运行一次**"的习惯，而不是攒完整个文件再跑

**延伸**：`NameError` 属于 `Exception` 子类，**能在运行时被 `try-except NameError` 捕获**——但不要在业务代码里靠捕获 `NameError` 来兜底拼写错误，那是掩盖问题。

### A3. 提前 `return` 打断外层的遍历

**现象**（`student_system.py::count_max_min_avg`）：
```python
for subj, score in cls_subjects_score.items():
    if score:
        ...
    else:
        cls_result[subj] = {...}
        return None        # ← 直接退出整个方法
```
一旦某班某科无人报分，方法**直接结束**，后续所有班级的统计全部丢失，连已算好的结果也不打印。

**根因**：把"跳过当前项"写成了"终止整个函数"。`continue` 与 `return` 一个是"本层跳过"，一个是"全栈退出"。

**解法**：
```python
else:
    cls_result[subj] = {...}
    continue              # 跳过该科目，继续下一个
```

**延伸**：**在循环里写 `return` 前，先自问三句**：① 我要退的是这一轮还是整个函数？② 我要退的是这一层还是所有层？③ 退的时候，已经算出来的部分数据是否需要带出去？

### A4. `if result:` 用"真值"判成败，撞上合法的 `0`

**现象**：
```python
result = triangle(bed, height)
if result is None:
    print("非法输入")
else:
    print(f"面积：{result}")
```
这里写 `is None` 是**正确**的。但同一套代码在别处大量使用：
```python
result = circle_area(radius)
if result:
    print(f"...{result:.2f}")
else:
    print("半径应为数字")
```
如果 `radius=0`（已被函数内部拦截，但若未拦截）→ `area = 0.0` → `if 0.0` 为 `False` → 会误报"半径应为数字"。

**根因**：Python 的 `0 / "" / [] / {} / None` 在布尔上下文中全为假。用"真值"承载"成功/失败"语义时，**合法的零值会被误判为失败**。

**解法**：三种模式择一，全程统一
```python
# 模式 A：用 None 表示失败，其余一切值（含 0）都是成功
if result is None: ...

# 模式 B：返回 (ok: bool, value) 二元组 —— 显式分离
ok, value = circle_area(r)
if not ok: ...

# 模式 C：失败抛异常，成功返回值（最 Pythonic）
try:
    area = circle_area(r)
except ValueError:
    ...
```

**延伸**：这是原始类型返回值的经典歧义问题。C 用 `-1`、Go 用 `(v, err)`、Python 用 `None` / 异常——**选一种并贯穿项目**，别混用。

## B 类 · 类型与接口错配

### B5. `map` 的返回值被当成原元素访问

**现象**（`函数进阶——匿名函数.py`）：
```python
for s in map(lambda x: x["score"] + 5, students):
    print(f"{s['name']} : {s['score']}")
# TypeError: 'int' object is not subscriptable
```
**根因**：`map` 的返回元素是**函数返回值**（这里是 `int`），不是原字典。`s` 已经是数字，无法再 `["name"]`。

**解法**：
```python
# 方案一：重新造字典
map(lambda x: {**x, "score": x["score"] + 5}, students)
# 方案二：直接返回新结构
map(lambda x: (x["name"], x["score"] + 5), students)
```

**延伸**：**`map` / `filter` 的返回值类型由"回调的返回值"决定，不是由"输入容器"决定**。这是函数式接口最容易混淆的点。同理 `filter` 返回的是**原元素**（只做筛选，不做变换），`map` 返回的是**新值**（做变换）——两者语义完全不同。

### B6. `int()` 与 `float()` 的字符串能力边界

**现象**：
```python
int("3.14")        # ValueError ❌
int(3.14)          # 3       ✅（截断，非四舍五入）
int(float("3.14")) # 3       ✅
float("3.14")      # 3.14    ✅
```
对面 JS：`parseInt("3.14")` → `3`（能解析前缀数字），`parseInt("abc")` → `NaN`（不抛错）。

**根因**：Python 的 `int(str)` 要求**严格整数格式**，不做前缀解析、不做隐式转换；JS 的 `parseInt` 会"尽力解析"。

**解法**：
1. 需要转整数 → 先 `float()` 再 `int()`
2. 统一封装校验函数（你已实践的重构方向）：
```python
def to_number(value) -> float | None:
    try:
        return float(value)
    except (ValueError, TypeError):
        return None
```

**延伸**：这是"**Python 比 JS 严格**"的典型体现——同样的转换在 JS 里静默降级，在 Python 里直接抛错。**严格是好事**：错误暴露得越早，调试成本越低。但代价是所有输入边界都必须显式处理。

### B7. `all()` 与 `any()` 的误用

**现象**（`函数基础——案例.py` 早期版本）：
```python
if all(0 <= n <= 100 for n in values):     # ✅ 正确：全部合法才算合法
```
但早期曾写成 `all(s > 100 or s < 0 ...)`，导致"任何值越界就通过校验"的反向逻辑。

**根因**：把"存在非法"（`any`）与"全部合法"（`all`）搞成了对偶。

**解法**：记住两个恒等式
```
all(合法条件)      ≡ 所有元素都合法
not any(非法条件)  ≡ 所有元素都合法
any(非法条件)      ≡ 至少一个非法 → 应拒绝
```

**延伸**：你的笔记里写了"**`all` 误用 → 发现后改为 `any()`**"，这条自我复盘很有价值。在输入校验这类场景，**建议只写一种正向形式并加注释**，不要在同一项目里让 `all` 和 `any` 混着表达同一语义，读代码的人会被绕晕。

### B8. `abs(float(x))` 之后仍判断 `< 0`（死代码）

**现象**（`student_system.py::add`）：
```python
course = [abs(float(s)) for s in course]
if any(s > 100 or s < 0 for s in course):    # s < 0 永远为 False
    print("成绩应在0~100之间，负数取绝对值")
```
**根因**：先取绝对值，再判断是否为负——后半句是**不可达代码**。

**解法**：明确业务语义
```python
# 语义一：负数视为输入错误（不自动纠正）
try:
    vals = [float(s) for s in course]
except ValueError:
    return None
if any(v < 0 or v > 100 for v in vals):
    return None

# 语义二：负数取绝对值，只校验上界
vals = [abs(float(s)) for s in course]
if any(v > 100 for v in vals):
    return None
```

**延伸**：`abs` 是一种**静默纠错**，会掩盖用户的输入错误。对成绩、金额、年龄这类业务字段，静默纠错往往比直接报错更糟——用户不知道自己的输入被篡改了。

### B9. 用字符串当枚举使用

**现象**（`第一学期测试.py`）：
```python
def judge_common_year(year) -> str:   # 返回 "闰年" / "平年" / None
    ...
def is_day():
    isyear = judge_common_year(input_year)
    if isyear == "闰年":              # ← 字符串字面量硬比较
```
**根因**：函数约定返回"中文字符串"，调用方靠**拼写一致的字符串**做分支。只要返回方改一个字（"闰年" → "是闰年"），调用方的判断**静默失效**，不报错但逻辑全错。

**解法**（按工程性递进）
```python
# ① 返回布尔值（最简）
def is_leap_year(year) -> bool: ...

# ② 返回枚举（最规范）
from enum import Enum
class YearType(Enum):
    LEAP = "闰年"
    COMMON = "平年"

# ③ 返回英文常量（次优）
LEAP, COMMON = "LEAP", "COMMON"
```
注意：`judge_common_year` 的 `except` 分支只 `print` 未 `return`，会返回 `None` —— 同样落入 **A1 类的坑**。

**延伸**：**凡是"只有几种取值"的含义，就应该用布尔/枚举/常量表达，而不是裸字符串**。字符串是给人看的，不是给控制流看的。

### C10. 字典视图（`keys()` / `values()` / `items()`）不可下标

**现象**（`数据容器——结尾-总结-综合案例.py`，自评"犯同样错误，视图没有下标"）：
```python
for name in self.OS.keys():
    value = self.OS[name]      # ✅ 正确：用键再去取值
```
早期版本尝试 `self.OS.values()[0]` → `TypeError: 'dict_values' object is not subscriptable`。

**根因**：`keys/values/items` 返回的是**动态视图对象**，不是列表。视图有 `__iter__` 但**没有 `__getitem__`**。

**解法**：
```python
list(d.values())[0]        # 先转列表（会快照，失去动态性）
next(iter(d.values()))     # 取第一个值（推荐，O(1)）
```

**延伸**：视图的"动态性"是特性不是 bug——`d.keys()` 拿到后，字典增删会实时反映到视图中。但这也意味着**遍历视图时修改字典**会抛 `RuntimeError: dictionary changed size during iteration`。正确做法：`for k in list(d.keys()): ...`。

### C11. `pop()` 在遍历中删除，或边界校验反了

**现象**（`学校线上网课/.../作业.py::delete`）：
```python
num = int(input("请输入你要删除的任务编号："))
if -1 <= num <= len(task):
    task2 = task.pop(num - 1)      # num=0 时 pop(-1) 删掉了最后一个
```
**根因**：校验区间写成 `-1 <= num`，而业务语义是"用户输入 1~N 的正整数编号"。

**解法**：
```python
if not (1 <= num <= len(task)):
    print("编号超出范围")
    return
item = task.pop(num - 1)
```

**延伸**：这是典型的 **off-by-one + 边界语义混淆**。"内部索引从 0 开始"与"用户看到的编号从 1 开始"之间必须**只有一个转换点**（`num - 1`），校验也必须针对用户视角（`1 <= num`）。

### C12. 遍历列表时删除元素

**现象**（`作业.py` 与 `5月12日——第一次网课/自学作业.py`）：
```python
for Text in myArray[:]:       # ✅ 用了切片拷贝，正确
    if text in Text:
        myArray.remove(Text)
```
而 `my_calculator.py` 的调用方：
```python
for num in number[1:]:        # ❌ 这是切片的新列表，但 remove 作用于原列表
    if num == num2:
        number.remove(num)    # 只删第一次出现的 0，同名元素会漏删
```
**根因**：
1. **原地遍历 + 删除** → 索引错位，跳过元素
2. `list.remove(x)` **只删第一个匹配**，多个相同值不会全删

**解法**：
```python
# 方案一：切片拷贝遍历（简单，O(n²)）
for item in original[:]:
    if cond(item):
        original.remove(item)

# 方案二：列表推导式重建（推荐，O(n)）
original = [x for x in original if not cond(x)]

# 方案三：倒序索引删除
for i in range(len(original) - 1, -1, -1):
    if cond(original[i]):
        del original[i]

# 方案四：while 循环（可读性好，O(n²)）
while target in original:
    original.remove(target)
```
你的笔记里已经明确写出："**使用 for 循环删除指定元素，列表长度会缩减，迭代可能会出问题，最好使用 while 循环**" —— 这条自省准确，建议升级为"**默认用列表推导式重建，只在内存极端敏感时才用倒序删除**"。

### C13. 中文引号混入代码

**现象**（`数据容器——字典dict-案例.py`）：
```python
print(f"{key}: 价格：{value["价格"]}，数量：{value["数量"]}")
```
在 Python 3.12 之前，f-string 内部不能复用同种引号（3.12 后允许嵌套同引号，但混用中文引号 `“”` 仍然会报 `SyntaxError: invalid character`）。

**根因**：切换输入法时未切回英文符号。

**解法**：

## D 类 · 文件与 IO

### D14. 备份文件无限增长 / 读取前未确认文件存在

**现象**（`读写、写入、追加操作...py::removes`）：
```python
with open('学生系统文件.txt', 'rt', encoding='utf-8') as f:
    lines = f.readlines()

with open('学生系统文件备份.txt', 'at', encoding='utf-8') as f:
    f.writelines(lines)              # 每次运行都追加 → 备份文件越滚越大
```
另外，`read1()` 直接打开 `'测试.txt'`，文件不存在会抛 `FileNotFoundError`。

**根因**：
1. 备份模式选了 `a`（追加）而非 `w`（覆盖），备份语义被破坏
2. 未做存在性检查

**解法**：
```python
from pathlib import Path

src = Path('学生系统文件.txt')
if not src.exists():
    print(f"文件不存在：{src.resolve()}")
    return

# 备份：覆盖式，或带时间戳
Path('学生系统文件备份.txt').write_text(
    src.read_text(encoding='utf-8'), encoding='utf-8'
)
```

**延伸**：`readlines()` 会把**整个文件读进内存**。文件 > 几百 MB 时应改成流式：
```python
with open(path, encoding='utf-8') as f:
    for line in f:              # 逐行迭代，内存 O(1)
        process(line)
```
你的 `for line in f` 笔记里已经提到这一点，只是代码里还没践行。

### D15. 删除操作依赖精确的字符串匹配格式

**现象**：
```python
if f'姓名：{del_name},' in line:
    continue
```
**根因**：用 `f"姓名：{name},"` 这种**带全角冒号、带逗号**的格式做子串匹配。只要写入端格式有任何一个字符变化（空格、半角/全角、换行位置），删除就静默失效（不报错、不删）。

**解法**：结构化存储优先于文本拼接

import json
# 写入

# 读取 + 过滤
records = [r for r in json.load(f) if r["姓名"] != del_name]

**延伸**：**"文本文件"不是"结构化存储"**。一旦需要按字段增删改查，就该升级为 JSON / CSV / SQLite。用 `in` 判断子串是最脆弱的数据操作方式——这也是为什么你的后续项目（学生管理系统）都改用了 `dict` 嵌套。

### D16. `open()` 忘写 `encoding`，跨平台乱码

**现象**：Windows 上默认 GBK 读取 UTF-8 文件 → `UnicodeDecodeError: 'gbk' codec can't decode byte 0xXX`。

**根因**：`open()` 的 `encoding` 默认值由 `locale.getpreferredencoding()` 决定，Windows 是 GBK，Linux 是 UTF-8。

**解法**：

**延伸**：你已理解 `str`（Unicode 抽象）↔ `bytes`（编码后的二进制）的转换边界。这条认知一旦稳固，所有"乱码"问题都能定位到"**哪一步用了哪个编码**"。

### E17. `obj.类属性 = v` 改不动类属性，只是原地遮蔽

### E19. `__add__` 里 `list + list` 拼接后 `sum()` 遇到非数字

**现象**：
```python
new_score = self.score + other.score               # list + list = 拼接
total_score = sum(float(s) for s in new_score)     # 元素含 dict 时 TypeError
```
`student4` 的 `score` 是 `{'score': 40}`（dict），一旦参与 `+` 就炸——好在被 `except (ValueError, TypeError)` 兜住，返回 `NotImplemented`。

**根因**：
1. 属性 `score` 的类型**不统一**（有时 `float`，有时 `list[float]`），`__init__` 用 `isinstance` 强行包装成 list，掩盖了类型混乱
2. `NotImplemented` 返回后 Python 尝试 `other.__radd__(self)`，也没有 → 抛 `TypeError: unsupported operand type(s)`

**解法**：
```python
def __init__(self, ..., score):
    # 入口处就把类型标准化，暴露错误
    if not isinstance(score, (int, float)):
        raise TypeError(f"score 必须是数字，收到 {type(score).__name__}")
    self.score = float(score)
    self.scores = [float(score)]      # 用两个字段表达"单值"和"历史"
```

**延伸**：**`NotImplemented` 是"我没实现"，不是"我实现失败了"**。前者让 Python 去试 `__radd__`，后者应抛异常。你的代码在语义上区分正确，但入口的类型约束偏松，导致"错误进得来、靠出口兜"。

### E20. `ShopGoverns.add_shop` 的失败分支会打印误导性提示

**现象**（`面向对象案例——课后作业.py`）：
```python
def add_shop(self, name, price, quantity):
    result1 = self.judgment_indata(name)     # 存在 → True；不存在 → None
    result = self.judgment_data(price, quantity)  # 合法 → tuple；非法 → None
    if result1 is None:                      # 商品不存在
        if result is not None:               # 且数据合法
            ...添加...
            return True
    print(f"商品：[{name}] 已在购物车中，请执行修改操作")   # ← 无差别兜底

当**价格非法**（`result is None`）时，走不到 `return True`，会落到最后一行，打印"**已在购物车中**"——错误归因。

**根因**：两个独立的失败原因（① 已存在 ② 数据非法）合并到了同一个出口，且提示只覆盖了原因 ①。

**解法**：**先判早退，让每个失败原因有独立出口**

if self.judgment_indata(name):

parsed = self.judgment_data(price, quantity)
if parsed is None:
    return None                     # judgment_data 内部已打印具体原因
self.shopping.append(Shopping(name, *parsed))
print(f"商品[{name}]添加成功")
return True
```

**延伸**：这是 **"卫语句（Guard Clause）"** 的教科书场景——**先处理例外，让主路径保持直线**。嵌套 `if` 超过两层，基本就该改成卫语句了。

### E21. `remove_shop` 中"边遍历边删除"

**现象**：
```python
for shop in self.shopping:
    if name == shop.name:
        self.shopping.remove(shop)
        return True          # ← 因为立刻 return，侥幸安全
```
**根因**：能在遍历中删除是"因为马上 return 了"，**并非逻辑上安全**。如果将来改成"删除所有同名商品"（去掉 `return`），就会漏删并可能 `IndexError`。

**解法**：
```python
# 方案一：列表推导式过滤
before = len(self.shopping)
self.shopping = [s for s in self.shopping if s.name != name]
return len(self.shopping) < before

# 方案二：倒序索引删除
for i in range(len(self.shopping) - 1, -1, -1):
    if self.shopping[i].name == name:
        del self.shopping[i]
```

**延伸**：**"能跑"和"正确"是两件事**。靠 `return` 提前退出规避的隐患，会在下一次需求变更时变成定时炸弹。写代码时应问：**如果去掉这个 `return`，它还对吗？**

total = chinese_score + math_score + english_score

**三条规律**：
1. **超过 60% 的坑来自"Python 与 JS 的默认行为差异"**（隐式转换、取整方向、越界行为、作用域）——你的 JS 背景是资产，但也是最大的"诱错源"。

### 一个典型案例：**输入校验的四份实现**

```python
# 版本 1（运算符案例）

        try: return float(input(value))
        except ValueError: print("不是数值类型，请重新输入!!!")

# 版本 2（几何计算器）
def circle(radius: float | str) -> ...:
    try:
        radius = abs(float(radius))
        if radius == 0: return {}
    except ValueError:
        return None

# 版本 3（购物车课后作业）
def judgment_data(self, price, quantity):
    try:
        return abs(float(price)), abs(int(quantity))
    except ValueError:
        return None

# 版本 4（期末题）
def is_score(prompt):
    while True:
        try:
            value = float(input(prompt))
            if 0 <= value <= 100: return value
            print("分数应该在0~100之间")
        except ValueError:
            print("请输出数字")
```

**四份代码解决同一个问题：带范围约束的安全数值输入**。差异只在"提示语"和"范围"。

**重构建议（一个 `validators.py` 就够）**：
```python
from typing import Callable

def read_number(
    prompt: str,
    *,
    cast: Callable[[str], float] = float,
    lo: float | None = None,
    hi: float | None = None,
    allow_abs: bool = False,
) -> float | None:
    """统一的安全数值输入。返回 None 表示用户放弃 / 非法。"""
    try:
        raw = input(prompt)
    except (EOFError, KeyboardInterrupt):
        return None
    try:
        val = cast(raw)
    except ValueError:
        print(f"请输入合法的{cast.__name__}")
        return None
    if allow_abs:
        val = abs(val)
    if lo is not None and val < lo:
        print(f"数值不能小于 {lo}"); return None
    if hi is not None and val > hi:
        print(f"数值不能大于 {hi}"); return None
    return val
```
**收益**：4 份 → 1 份，行为一致，改一次提示语全项目生效。
