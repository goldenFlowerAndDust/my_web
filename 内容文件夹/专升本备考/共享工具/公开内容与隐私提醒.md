# 公开内容与隐私提醒

这个仓库如果部署在 GitHub Pages 或公开仓库，下面这些内容可能被任何人看到、搜索到、复制或 fork。

上传前请逐项检查。**不确定时不要提交，不要推送。**

## 一、会公开的内容

### 1. AI 答疑历史归档

```text
备考专升本英语/英语答疑/答疑历史.json
备考专升本数学/数学答疑/答疑历史.json
```

里面包含：

```text
提问原文
AI 完整回答
分类（单词解释 / 作文 / 句子分析 / 题目讲解等）
时间
数学题的知识点
```

这些是完整问答，不是摘要。  
如果提问里出现真实姓名、学校、身份证号、手机号、住址、账号、病情、家庭情况、聊天记录等内容，都会一起公开。

### 2. 添加日志归档

```text
备考专升本英语/添加日志/添加日志.json
```

里面包含：

```text
添加过的单词
添加时间
分类 / 目标页面
复习日程
```

`添加日志/*.html` 里已经有按天公开的类似内容，上传 JSON 不会额外增加太多类型，但仍请检查是否包含不想公开的单词或时间规律。

### 3. 已经公开的页面

```text
备考专升本英语/添加日志/*.html
备考专升本英语/添加日志/index.html
```

这些页面本身就会展示添加记录。  
如果不想让单词列表公开，也不要把这些页面提交到公开仓库。

### 4. Worker / SCF 代码

```text
cloudflare-worker/worker.js
tencent-scf/index.js
```

代码本身不应该包含 API Key、访问口令或 `PROXY_TOKEN`。  
它们应只存在于：

```text
Cloudflare Worker Secret
腾讯云 SCF 环境变量
本机 共享配置/口令.txt
本机 共享配置/云端同步.json
```

如果代码里出现真实 Key / Token，立刻停止提交并更换。

## 二、不应公开的内容

以下内容已经加入 `.gitignore` 或本机 `.git/info/exclude`，不要强制提交：

```text
共享配置/口令.txt
共享配置/云端同步.json
共享配置/同步状态.json
共享配置/API.txt
备考专升本英语/词素工具/英语问答日志/*.jsonl
备考专升本数学/数学工具/数学问答日志/*.jsonl
备考专升本数学/数学工具/数学问答日志备份/
各科 导出记录/
词素工具/backups/
词素工具/review_backups/
想要自行搭建并使用的前提——第一步/部署/
浏览器测试 profile / 缓存
```

其中：

- `口令.txt`：DeepSeek API Key + 两条线路访问令牌
- `云端同步.json`：同步器使用的地址和口令
- `API.txt`：本地服务使用的 API Key
- 原始 JSONL：完整本地日志，未脱敏
- `部署/`：部署截图可能包含账号 ID、控制台信息、域名、账单等
- `导出记录/`：云端原样导出，含完整问答

## 三、公开后的风险

- 搜索引擎和第三方可能缓存归档内容
- 别人可以 fork、下载、二次发布
- 删除 Git 中的文件不会自动删除历史提交里的旧版本
- GitHub Pages 的内容会通过 CDN 缓存
- 问答中可能包含个人隐私、账号信息、代码中的密钥
- 单词记录可能暴露学习计划、作息和兴趣

## 四、上传前检查清单

### 1. 看当前改动

```powershell
git status --short
git diff --cached --stat
```

### 2. 确认没有把私密文件加进来

```powershell
git ls-files | Select-String "口令|云端同步|同步状态|API.txt|英语问答日志|数学问答日志|导出记录|部署/"
```

如果没有输出，说明这些文件没有被 Git 跟踪。

### 3. 检查归档内容

提交前手动打开：

```text
备考专升本英语/英语答疑/答疑历史.json
备考专升本数学/数学答疑/答疑历史.json
添加日志/添加日志.json
```

至少搜索：

```text
真实姓名
手机号
身份证
学校
地址
账号 / 密码
sk-
Bearer
token
```

### 4. 检查代码里有没有密钥

```powershell
git grep -n -I -E "sk-[A-Za-z0-9]|Bearer [A-Za-z0-9]|X-Tutor-Token.*[A-Za-z0-9]{16,}"
```

只应看到变量名、占位符或说明，不应看到真实值。

### 5. 确认 `.gitignore` 生效

```powershell
git check-ignore -v 共享配置/口令.txt
git check-ignore -v 共享配置/云端同步.json
git check-ignore -v 词素工具/英语问答日志/单词解释.jsonl
```

应该有输出。没有输出就说明路径没被忽略，先补规则。

## 五、如果已经误传了密钥

1. 立刻在对应平台更换：
   - DeepSeek API Key
   - Worker `TUTOR_ACCESS_TOKEN`
   - SCF `PROXY_TOKEN`
   - SCF `UPSTREAM_TOKEN`
2. 删除 Git 历史中的泄露文件，而不只是删除当前文件：

```text
git filter-repo
或 BFG Repo-Cleaner
```

3. 强制推送清理后的历史，并通知协作者重新克隆。
4. 检查 GitHub Actions、Releases、Issues、Gist、缓存页面是否还有副本。

**只执行 `git rm` 不够。旧提交仍然包含内容。**

## 六、两种使用策略

### 策略 A：公开旧历史，GitHub 永久显示

提交：

```text
英语答疑/答疑历史.json
数学答疑/答疑历史.json
添加日志/添加日志.json
```

优点：

- GitHub 和本地显示一致
- 不受云端 24 小时删除影响
- 移动端新问题在 KV，旧历史在 JSON

缺点：

- 完整问答和添加记录公开
- 每次本地新增后要重新生成并上传归档

### 策略 B：不公开归档，只保留云端

不提交上述 JSON。

优点：

- 仓库不直接公开问答和单词记录
- 云端有访问口令保护

缺点：

- GitHub 只能显示云端 24 小时内记录
- 本地旧历史不会出现在 GitHub
- 超过 24 小时且没有本地归档上传时，GitHub 看不到

## 七、建议

- 公开仓库只放代码、模板、无隐私的示例
- 完整历史放本机或私有仓库
- 确实要公开时，先通读归档，删掉个人隐私
- 不要为了“看起来完整”而提交 `口令.txt`、`云端同步.json`、原始 JSONL 或部署截图
- 任何访问口令一旦进入公开提交，就视为已泄露并立即更换
