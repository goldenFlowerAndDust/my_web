# AI 答疑上下文改造计划

## 目标

- 一个标签 = 一个对话。
- 同一标签内，后续提问携带最近消息。
- 点击 `+` 新建标签时，上下文为空。
- 英语 / 数学：最多 8 轮。
- 编程：最多 20 轮，可后续再调 10～20。
- 达到上限后停止发送，提示新建对话。
- 只发送当前标签的最近消息，不发送其他标签内容。
- 英文、数学、编程本地服务和 Worker 都支持 `history` 字段。
- 保持现有新窗口、检查修复、同步和相对路径逻辑不变。

## 上限

```text
英语 / 数学：8 轮（16 条 user/assistant 消息）
编程：20 轮（40 条消息）
```

一轮 = 1 次用户提问 + 1 次 AI 回答。

## 网络协议

请求体增加可选字段：

```json
{
  "question": "当前问题",
  "history": [
    {"role": "user", "content": "上一轮问题"},
    {"role": "assistant", "content": "上一轮回答"}
  ]
}
```

规则：

- 前端只传 user / assistant。
- 不传 system。
- 后端校验角色和长度。
- 后端拼接固定 system + history + 当前问题。
- 后端再次裁剪历史，防止绕过前端上限。
- 消息保持追加顺序，利于 DeepSeek 前缀缓存。

## 实施阶段

1. 英语/数学标签保存 messages，限制 8 轮，暴露 `TutorTabs`。
2. 编程标签保存 messages，限制 20 轮。
3. 英语/数学共享 `上下文.js` 包装 `/api/tutor` 请求，自动补 history 并记录成功回答。
4. 编程 app 直接补 history 并记录。
5. 三个本地服务接收 history。
6. Worker 接收 history。
7. 验证同标签追问、新标签无上下文、上限阻止、相对路径和旧机制不受影响。
