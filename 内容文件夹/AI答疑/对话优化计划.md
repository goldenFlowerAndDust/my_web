# AI 对话优化计划（轮次定位 / Token 成本 / 历史分组）

## 总原则

- 一个标签 = 一个对话。
- 第一轮问题作为对话标题。
- 对话内轮次下拉：当前轮必须自动定位到最新回答，不再需要手动切回。
- 历史记录按“对话”分组，而不是一个回答一条。
- 每个对话显示第一轮标题，展开后下拉查看第 2～N 轮。
- 回答区内部滚动，不拉长整页。
- token 和人民币按 DeepSeek 返回的实际 usage 计算，并标明是估算。
- 不改现有检查/修复、同步、新窗口逻辑。

## 阶段 1：轮次自动定位

### 问题

英语已验证 1、2 轮和解释联动，但新回答完成后老师回答框仍停留在第一轮，需要手动调整。

### 方案

- 每次成功追加一轮，强制轮次下拉选中最新一轮。
- 同时把回答面板内容切到最新一轮。
- 切换标签时也默认最新一轮，不沿用上一个标签的下拉位置。
- 编程、英语、数学三处都按同一行为处理。

### 验收

```text
第1轮完成后：下拉选中第1轮，回答显示第1轮
第2轮完成后：下拉自动选中第2轮，回答显示第2轮
切换到别的标签再切回来：显示该标签最新一轮
手动选择旧轮次：只切换显示，不改上下文
```

逐页检查，不通过不进入下一阶段。

## 阶段 2：Token 与 RMB

### 后端

DeepSeek 响应中的：

```json
"usage": {
  "prompt_tokens": 0,
  "completion_tokens": 0,
  "total_tokens": 0
}
```

保留到接口返回：

```json
{
  "usage": {
    "prompt_tokens": 0,
    "completion_tokens": 0,
    "total_tokens": 0
  },
  "cost": {
    "input_cny": 0,
    "output_cny": 0,
    "total_cny": 0
  }
}
```

本地英语、数学、编程服务和 Worker 都要返回。

### 价格

使用可配置的人民币价格，不能把估算说成实际扣费：

```text
输入：每百万 token 人民币价格
输出：每百万 token 人民币价格
```

默认价格放在共享配置中，前端只展示，不硬编码多份。

### UI

- 回答底部显示：

```text
本次：输入 1234 / 输出 567 / 合计 1801 tokens
估算：¥0.0123
```

- 问题类型卡片最下面加说明：

```text
每次回答按 DeepSeek 实际用量估算，价格以共享配置为准。
```

### 验收

```text
英语回答后出现 token 行
数学回答后出现 token 行
编程回答后出现 token 行
没有 usage 时显示“未返回用量”，不显示 0 冒充
价格换算与配置一致
```

## 阶段 3：历史按对话分组

### 目标

不再一个回答一条历史，而是：

```text
[第一轮问题标题]  共 N 轮  ▾
  第1轮 · 问题
  第2轮 · 问题
  第3轮 · 问题
```

点击标题或下拉选择轮次，显示对应回答。

### 数据

- 每个对话有稳定 conversation id。
- 第一轮问题作为 title。
- 后续轮次只追加到该对话。
- 服务端日志保留原记录，但历史 UI 按 conversation id 分组。
- 旧的单条日志兼容为单轮对话。

### 验收

```text
完成2轮后，历史只出现1个对话
标题=第1轮问题
展开后能看到第1轮、第2轮
点击第2轮显示第2轮回答
刷新页面后分组仍在
新建标签不会混入旧对话
```

## 执行顺序

2. 阶段 1 实现 + 验证。
3. 阶段 2 实现 + 验证。
4. 阶段 3 实现 + 验证。
5. 提交推送。
