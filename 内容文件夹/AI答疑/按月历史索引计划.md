# 按月历史索引执行计划

## 目标

历史界面不要一次加载全部问答。

```text
月份索引
→ 当前月窗口摘要
→ 需要看回答时再加载详情分片
```

本地 JSON 仍是长期数据源，云端仍是临时中转。

## 数据目录

```text
AI答疑/历史/
  english/
    index.json
    2026-11/
      index.json
      chunk-0001.json
      chunk-0002.json
  math/
    index.json
    2026-11/
      index.json
      chunk-0001.json
  code/
    index.json
    2026-11/
      index.json
      chunk-0001.json
```

## 规则

- 月归属：按窗口 `updated_at` 所在月份，继续提问会进入最新月份。
- 去重：按 `window_id`，同一窗口取 `updated_at` 最新。
- 删除：使用 `deleted` 墓碑；墓碑不早于窗口更新时间则删除。
- 每个详情分片最多 100 个窗口，且不超过 2MB；只有超过 5MB 才作为硬错误。
- 分片只能在窗口边界切，不能把一条问答拆开。
- 前端首屏只读 `index.json` 和当前月 `index.json`。
- 点击某个对话后才读取对应 chunk；后续再做自动预取第一页。
- GitHub Pages 只读静态 JSON，不写回；本地重新生成并推送后更新。

## 阶段 1：生成器

- 新建 `共享配置/生成历史索引.py`。
- 读取三科本地 JSON。
- 按 `updated_at` 月份分组。
- 生成 `index.json`、月 `index.json`、详情 chunk。
- 校验：窗口总数一致、无重复 ID、分片不超过限制。

## 阶段 2：本地服务接口

- 三个服务增加：
  - `GET /api/history/index`
  - `GET /api/history/month?month=YYYY-MM`
  - `GET /api/history/chunk?month=YYYY-MM&chunk=chunk-0001.json`
- 只读生成后的文件。
- 校验：HTTP 200，内容与文件一致。

## 阶段 3：前端月份筛选

- 历史区增加月份下拉框。
- 默认当前月。
- 切换月份只请求该月 `index.json`。
- 列表先显示标题、时间、轮数摘要。

## 阶段 4：详情按需加载

- 点击对话时请求对应 chunk。
- 同一 chunk 在页面内缓存。
- 不一次加载整月所有 messages。
- 校验：切换月份不加载其他月份 chunk。

## 阶段 5：同步后重新生成

- `同步全部科目` 合并云端后重新生成索引。
- 回答完成后也重新生成索引。
- 校验：新增/继续提问后，月份列表和摘要立即更新。

## 阶段 6：全量校验

- 三科互不串。
- 月度索引数量等于本地窗口数。
- 去重正确。
- 删除墓碑正确。
- 切月只加载当前月。
- 点击详情才加载 chunk。
- 5MB 硬上限和 2MB/100 窗口分片正确。

## 约束

- 不修改 `worker.js`。
- 如果必须改 Worker，暂停并交给用户手动部署。
- 每个阶段先校验，再进入下一阶段。
