# AI 历史统一改造计划

## 目标

- 英语 / 数学 / 编程历史彻底隔离。
- 每个问答窗口是 JSON 的一个 key。
- 窗口内保存连续问答和轮次。
- 英语、数学最多 8 轮；编程最多 20 轮。
- 删除某一轮立即释放轮次数量，可以继续加入。
- 本地和云端读取同一份 JSON 结构。
- 每天归档一次。
- 不把问题归因于 Worker 配置；先验证数据层。

## 最终数据模型

每个科目一份：

```text
内容文件夹/AI答疑/对话历史/english.json
内容文件夹/AI答疑/对话历史/math.json
内容文件夹/AI答疑/对话历史/code.json
```

结构：

```json
{
  "version": 1,
  "subject": "english",
  "updated_at": "2026-11-05 20:00:00",
  "windows": {
    "window-id": {
      "title": "第一轮问题",
      "created_at": "...",
      "updated_at": "...",
      "max_rounds": 8,
      "rounds": 2,
      "messages": [
        {"role": "user", "content": "..."},
        {"role": "assistant", "content": "..."}
      ]
    }
  }
}
```

编程：

```text
max_rounds: 20
```

## 窗口规则

```text
一个标签 / 一次继续提问快照 = 一个窗口 key
窗口内只能追加连续问答
英语/数学满 8 轮停止
编程满 20 轮停止
删除任意一轮后轮次减少，立即可以继续提问
删到 0 轮 = 删除窗口
```

## 同步规则

- 本地服务读本地 JSON。
- Worker 读云端同一结构 JSON。
- 同步脚本下载云端 JSON 覆盖/合并本地，上传本地 JSON。
- 页面历史只读当前科目 JSON。
- 不再把服务端 `tutor-log` 的单条问答当作历史主数据。
- 旧单条日志只做一次性迁移，不作为长期来源。

## 阶段

### 阶段 1：数据模型

- 新建 `对话历史` 目录和三科 JSON。
- 统一结构为 `windows` 对象。
- 英语/数学 8，编程 20 写入 `max_rounds`。
- 校验：三科文件互不包含对方记录。

### 阶段 2：轮次限制与删除释放

- 追加时检查窗口轮数。
- 删除轮次从 messages 删除对应 user/assistant 对。
- 如果删到 0 轮，删除窗口。
- 校验：删一轮后还能继续提问，数量立即恢复。

### 阶段 3：本地服务 API

- 英语 8767、数学 8768、编程 8769 增加：
  - `GET /api/conversations`
  - `POST /api/conversations`
- 只读写对应科目 JSON。
- 校验：接口返回的结构和文件一致。

### 阶段 4：Worker 同一 JSON

- Worker 增加同一结构的 KV 读写：
  - `key = conversations:english/math/code`
- 不再用单条 tutor-log 作为历史来源。
- 校验：本地 JSON 与云端 JSON 字段一致。

### 阶段 5：前端切换

- 历史、轮次、快照统一用窗口 JSON。
- 本地/云端都请求同一 `/api/conversations`。
- 删除轮次同步服务端。
- 校验：同窗口跨刷新、跨线路仍在。

### 阶段 6：每日归档

- 每天把三科 JSON 归档一份：
  `历史归档/YYYY-MM-DD/{english,math,code}.json`
- 校验：归档 JSON 与当天源 JSON 内容一致。

### 阶段 7：全量校验

- 三科隔离
- 8/20 上限
- 删除释放
- 继续提问
- 本地/云端同结构
- 每日归档
- 旧日志迁移一次

## 当前先做什么

先做阶段 1、2：数据模型和轮次规则。

这一步不依赖 Worker，也不依赖网络，先把“历史到底以什么为准”定死。
