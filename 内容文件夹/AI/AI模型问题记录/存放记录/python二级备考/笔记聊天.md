方式二：collections.deque(推荐)

普通队列 VS 循环队列
普通队列
用一段连续空间存储
队尾入队、对头出队
缺点：
出队后前面的空间无法复用，可能导致'假溢出'(队尾已满，但前面有空位)
计算入队后的新队尾位置——适用普通队列：rear = rear + 1
计算入队后的新队首位置——适用普通队列：front = front + 1
循环队列
把数组在逻辑上连成环
入队/出队时指针可以绕回到数组开头
优点：
空间可以复用，不会出现'假溢出'。但是元素超出限制，会'真溢出'
关键公式(循环队列)
当 front == rear 时，队列为空
当 (rear + 1) % 容器 == front 时，队列为满 (牺牲一个存储单元)
计算入队后的新队尾位置——适用循环队列：rear = (rear + 1) % 容量
计算入队后的新队首位置——适用循环队列：front = (front + 1) % 容量
队列长度 = (rear - front + 容量) % 容量

关系模式类型题
关系模式：
一般通过
#
来确定主键、如果有多个则
#
组合成一个主键
主属性：
就是组成主键的各个字段（如 S#、C#）”。
非主属性：
就是主键以外的所有字段
部分依赖：
某个字段、与主键其中一个产生依赖
完全依赖：
某个字段、与主键所有产生依赖
平凡依赖：
某个字段是集合的子集(主键、字段集合)
传递依赖：
某个字段通过其他非主属性字段，将自身依赖主键
第一范式(1NF)：
所有属性(字段)都
不可再分
，每个单元格只有一个数据
第二范式(2NF)：
在满足1NF的基础上、
不允许非主属性依赖主键的一部分（但允许依赖主键的全部，或者通过别的字段传递依赖）
第三范式(3NF)：
在满足2NF的基础上，
不允许非主属性依赖主键的一部分，也不允许非主属性传递依赖于主键
