作用域

什么是作用域

  • 作用域就是一个变量可以生效的范围
  • 变量不是在所有地方都可以使用，而是这个变量的使用范围就作用域

  • 作用域分为两种(全局作用域、局部作用域≈函数作用域+块级作用域)

    1. 全局作用域

      • 全局作用域就是最大的作用域
      • 在全局作用域下，定义的任何变量和方法在任何地方都可以使用
      • 主要是：页面打开的时候，浏览器会自动生成一个全局作用域 window（或者“全局对象”）
      • 声明周期：页面打开时创建，关闭时销毁
      • 优点
        1. 全局任何地方都能访问，方便共享数据
        2. 适合存储全局配置、工具函数等，但应尽量避免滥用，以免命名冲突
        3. 可以直接在浏览器开发者工具中访问
        4. 局部作用域同样也可以访问
        缺点
        1. 容易造成命名冲突(多个代码段使用同名全局变量会相互覆盖)
        2. 使用关键字let,const重复命名，在全局作用域下会直接报错
        3. 变量常驻内存，可能导致内存浪费
        4. 代码耦合高，维护困难
        5. 容易被无意修改，产生难以追踪的bug

      局部作用域

      • 局部作用域包含:函数作用域和块级作用域
      • 块级作用域
        1. 定义:由{}配合let、const形成的区域(如if、for、while、单独{})
        2. 因为var的穿透性，所以var没有块级作用域
        3. 特点：存在暂时性死区(TDZ)，变量在声明前不可访问(预解析提前类似与let关键字)
        4. 优点
          • 更精细的变量控制、避免变量泄露到整个函数
          • 例如：for循环中用let声明的计数器只在循环内有效，
            不会有var导致的循环计算污染问题
          • 防止在块外部意外访问内部私有变量
          缺点
          • 不熟悉(let/const)的开发者可能会误以为var也有块级作用域，导致bug
          • 块级作用域内的函数声明行为较复杂(ES6不同环境下有差异)，所以建议少用块级作用域包裹函数
        函数作用域
        1. 与块级作用的区别：在函数内部用var、let、const声明的变量，均只能在函数内部访问
        2. 特点：var声明的变量会提升到函数顶部，但赋值留在原地
        3. 因为函数作用域有绝对的安全性：var不能穿透,所以不需要通过块级作用域包裹
        4. 但是还是会受全局作用的var影响，所以在开发当中尽量避免使用var声明变量
        5. 优点
          • 变量不会污染全局，避免命名冲突
          • 函数执行完后，大部分局部变量可被垃圾回收，节省内存
          • 封装内部逻辑，外部无法直接访问和修改
          缺点
          • 变量只在函数内部有效，如果多个函数需要共享数据，必须通过参数或关键字(return)返回值传递
          • 过度嵌套可能导致"回调地狱"(但这是编码风格问题，不是作用域本身的缺点)
      • 总结对比表
        总结对比表
        作用域类型 可见范围 适用关键字 优点 缺点
        全局作用域 所有位置 var、let、const在全局声明 方便共享 容易冲突、常驻内存、难维护
        函数作用域 函数内部 var、let、const 封装、避免污染、可回收 多个函数需要传参共享数据
        块级作用域 {}内部 let、const 更精细控制、避免变量泄露 行为需注意，函数声明兼容性问题

变量使用规则(分两种:访问规则和赋值规则)

  • 访问规则

    1. 当想获取一个变量的值的时候，称这个行为叫做访问

    2. 获取变量的规则(读值)

      • 从 当前作用域 开始查找变量
      • 如果有，就直接使用（内层变量遮蔽外层同名变量）
      • 如果没有，就去 外层作用域 查找，直到全局作用域
      • 如果全局也没有，则报错 ReferenceError: xxx is not defined。)
      • 口诀：(从内向外，就近使用)
      • 实例

  • 赋值规则(写值)

    1. 当想给一个变量赋值的时候，需要先找到这个变量，才能给它赋值

    2. 变量赋值规则

      • 同样从 当前作用域 开始查找变量
      • 如果找到，就直接赋值修改
      • 如果一直找到全局作用域都没找到，那么：
        1. 非严格模式：在全局对象上自动创建该变量并赋值（隐式全局变量）
        2. 严格模式（"use strict"）：直接报错，不会创建全局变量
        3. 注意:赋值不声明变量（例如 x = 10）时，容易意外产生全局变量，强烈建议使用 let / const / var 显式声明。

补充知识

  • 遮蔽(shadow)和覆盖(overwrite)

    遮蔽(shadow)和覆盖(overwrite)
    术语 含义 典型场景 是否影响外层变量
    遮蔽 内层作用域声明了同名变量，外层变量在内层不可见 let、const在嵌套作用域中 否（外层变量值不变，只是被“挡住”）
    覆盖 同一个变量被重新赋值，旧值丢失 var 重复声明，或 let a=1; a=2; 是（变量本身的值变了）

    注意：

    1. 遮蔽效果:作用域、嵌套
    2. 覆盖:var重复声明变量或重复赋值、let重复赋值、const没有覆盖操作
