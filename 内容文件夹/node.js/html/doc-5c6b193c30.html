第三节课 ｜ fs 模块：同步 / 异步读写文件

数据来源：课堂/第三节课/第三节课-总结.md · 更新于 2026-11-10

板块定位：Node 第一次真正碰「磁盘」。重点不是背 API，是理解同步与异步的区别以及回调风格。本板块已有文件：dom1.js（自定义模块）、dom2.js（读写练习）、hello.txt、txt2.txt、package.json

一、重点

  1. fs 是内置模块，require('fs') 直接用，不需要 npm 安装。
  2. 每个常用操作都有两套：异步（回调） 和 同步（...Sync）。
  3. 异步回调的固定形状是 (err, data) —— 错误在前，这是 Node 的通用约定。
  4. 同步方法出错会 throw，必须 try / catch；异步方法出错只把 err 传给你，不 catch 就永远不知道。

二、API 速查

操作异步（回调）同步备注
读文件fs.readFile(path, 'utf-8', cb)fs.readFileSync(path, 'utf-8')不传编码返回 Buffer
写文件fs.writeFile(path, data, cb)fs.writeFileSync(path, data)默认覆盖，文件不存在则创建
追加fs.appendFile(path, data, cb)fs.appendFileSync(...)等价于 flag: 'a'
删除文件fs.unlink(path, cb)fs.unlinkSync(path)
重命名/移动fs.rename(old, new, cb)fs.renameSync(...)
读目录fs.readdir(path, cb)fs.readdirSync(path)
查看是否存在—fs.existsSync(path)只有同步版
Promise 版fs.promises.readFile(...)可 await第五节课开始用

writeFile 的 options：{ encoding: 'utf-8', flag: 'a' }，flag 常见值：w 覆盖、a 追加、r 只读（写会报错）、wx 存在就报错。

三、写法模板

const fs = require('fs')

// 异步：err 在前，不写 if (err) 就等于把错误吞了
fs.readFile('./hello.txt', 'utf-8', (err, data) => {
    if (err) return console.error('读取失败：', err.message)
    console.log(data)
})

// 同步：没有回调，出错抛异常，必须 try/catch
try {
    const data = fs.readFileSync('./hello.txt', 'utf-8')
    console.log(data)
} catch (err) {
    console.error('读取失败：', err.message)
}

// 追加写（不覆盖）
fs.appendFile('./txt2.txt', '新的一行\n', 'utf-8', (err) => {
    if (err) return console.error(err)
    console.log('追加成功')
})

四、你笔记里做得对的地方

  • 同步/异步对照注释写得很清楚（readFile vs readFileSync、writeFile vs writeFileSync）；
  • 知道 flag: 'a' 是追加，且用 writeFile 也能追加；
  • 已经踩到「异步回调顺序不保证」这个坑（第四节课的笔记里写得更透）。

五、容易遗漏 / 建议修正

1. 你装了 fs 这个 npm 包，但它是个空壳

package.json 里写着 "fs": "^0.0.1-security"。node_modules/fs 里只有一个 package.json 和 README，作者是 npm/security-holder —— 这是 npm 官方为了防止有人抢注包名而放的占位包，里面没有代码。

require('fs') 走的是 Node 内置 fs，跟这个包无关。建议：

npm uninstall fs

记住：fs、path、http、url、os、crypto 这些是内置模块，永远不需要 npm install。真正需要装的是 axios、express、moment 这类第三方包。

2. 「异步丢给多线程」的说法要修正

你在注释里写「先将异步执行程序丢给多线程，执行完所有主线程后再执行」。更准确的说法：

  • Node 的 JavaScript 运行在单线程事件循环上；
  • 文件读写这种阻塞操作由 libuv 交给线程池（默认 4 个线程）去做；
  • 做完后把回调放进队列，等主线程空闲时执行。

所以不是「主线程全部执行完才执行异步」，而是「主线程同步代码跑完 → 事件循环取队列里的回调」。

3. 值得补的细节

  • readFile 不带编码时 data 是 Buffer，打印出来是 <Buffer 68 65 6c...>，要 .toString() 或传 'utf-8'；
  • 中文乱码基本都是「写的时候 utf-8、读的时候没指定编码」造成的；
  • 同步 API 会卡住整个进程，写服务器时绝不能用 readFileSync 处理用户请求；
  • fs.writeFile 覆盖式写入，内容一写就没了，改数据前先备份（第四节课的笔记里你自己也强调了）；
  • 异步回调里 return 只是结束这个回调，不会让外层函数停下——多个异步串联要靠嵌套或 async/await。
