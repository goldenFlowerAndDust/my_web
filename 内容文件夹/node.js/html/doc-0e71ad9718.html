第六节课 ｜ 异步执行扩展：Promise 与 async/await

数据来源：课堂/第六节课——异步执行扩展/第六节课-总结.md · 更新于 2026-11-10

板块定位：把前几节课的「回调嵌套」换成「链式 / 同步写法」，这是后面写接口、连数据库的必备语法。本板块已有文件：JavaScript_Promise_异步操作示例.docx（讲义），作业在 作业/第三次作业

一、为什么要有 Promise

回调写法在多层嵌套时会变成「回调地狱」，而且错误要一层层手动传递：

readFile(a, (err, d1) => {
    if (err) return ...
    readFile(b, (err, d2) => {
        if (err) return ...
        readFile(c, (err, d3) => { /* 三层，还不算业务逻辑 */ })
    })
})

Promise 把「将来的结果」变成一个对象，可以 await，也可以 .then 链式处理，错误统一 catch。

二、三个状态（重点）

状态含义能否再变
pending进行中可以变成下面两种之一
fulfilled成功（resolve）❌ 不可逆
rejected失败（reject）❌ 不可逆

「不可逆」是常考点：resolve 之后再去 reject 是无效的。

三、写法模板

// 1. 造一个 Promise
function fetchUser(id) {
    return new Promise((resolve, reject) => {
        console.log('开始请求')            // ← 注意：执行器是【同步】执行的
        setTimeout(() => {
            id > 0 ? resolve({ id, name: '张三' })
                   : reject(new Error('用户不存在'))
        }, 1500)
    })
}

// 2. .then / .catch 写法
fetchUser(1)
    .then(user => console.log('收到', user))
    .catch(err => console.log('出错', err.message))
    .finally(() => console.log('结束，成功失败都会执行'))

// 3. async / await 写法（推荐）
async function main() {
    try {
        const user = await fetchUser(1)
        console.log('收到', user)
    } catch (err) {
        console.log('捕获', err.message)
    }
}
main()

四、方法速查

API作用关键点
Promise.resolve(v)造一个已成功的 Promise常用在函数返回值统一
Promise.reject(e)造一个已失败的 Promise
.then(onOk, onErr)注册回调返回新的 Promise，所以能链式
.catch(fn)捕获链上任意一环的错误等价于 .then(null, fn)
.finally(fn)无论如何都执行不改变结果，不算「处理」
Promise.all([...])全部成功才成功一个失败就整体失败
Promise.allSettled([...])等全部结束不会因单个失败而中断
Promise.race([...])第一个结束的说了算成功或失败都算
Promise.any([...])第一个成功的说了算全失败才 reject

五、讲义里讲透的部分

  • 三种状态、pending → fulfilled/rejected 的转换；
  • .then/.catch 与 await 两种写法的对照；
  • 用 setTimeout 模拟网络请求、用 fetch 请求真实接口；
  • 一句话总结很到位：「.then/.catch 是注册回调，状态改变时才执行」。

六、容易遗漏（讲义没覆盖，但马上会用到）

1. new Promise(...) 里的代码是同步立刻执行的

console.log('开始请求') 不等 then，创建 Promise 的那一刻就打印了。只有 resolve 之后的 .then 才排进微任务。

2. async 函数永远返回 Promise

async function f() { return 1 }
f().then(v => console.log(v))  // 1

async function g() { throw new Error('x') }   // 等价于 return Promise.reject
g().catch(e => console.log(e.message))

所以 await 一个非 Promise 值也没问题，会被包一层。

3. await 不会阻塞主线程

它只「挂起当前 async 函数」，主线程继续跑后面的同步代码。这也是为什么 main() 后面的 console.log 会先执行。

4. 串行 vs 并行（性能差别很大）

// ❌ 串行：两个请求一个等一个
const a = await fetch(url1)
const b = await fetch(url2)      // 总耗时 = t1 + t2

// ✅ 并行：同时发起
const [a, b] = await Promise.all([fetch(url1), fetch(url2)])   // 总耗时 = max(t1, t2)

5. 忘了 return / await 是最常见的 bug

const user = getUser(1)          // ❌ 拿到的是 Promise，不是用户
const user = await getUser(1)    // ✅

6. 未处理的 rejection 会让 Node 直接崩

await 不写 try/catch、.then 不接 .catch，进程会抛 UnhandledPromiseRejection。所有异步入口都要有兜底。

7. fetch 只有在网络层失败时才 reject

HTTP 404 / 500 不会进 catch，必须自己判断：

const res = await fetch(url)
if (!res.ok) throw new Error('状态码：' + res.status)
const data = await res.json()   // .json() 也是异步，也要 await

8. 宏任务 / 微任务的顺序（面试常问）

console.log(1)
setTimeout(() => console.log(2), 0)
Promise.resolve().then(() => console.log(3))
console.log(4)
// 输出：1 4 3 2   （微任务先于宏任务）
