第八节课 ｜ url 模块：解析与拼接地址

数据来源：课堂/第八节课——URL模块/第八节课-总结.md · 更新于 2026-11-10

板块定位：服务器收到的 req.url 只是一串字符串，要从中取出路径、参数，就得靠 URL 解析。这是「路由 / 分页 / 搜索」的前置技能。本板块已有文件：URL模块.js（只有 parse + format 两行，笔记最薄的一个板块，建议重点补）

一、模块的作用

把一个 URL 字符串拆成结构化字段，或者反过来把字段拼回字符串。

https://user:pass@example.com:8080/api/list?id=1&page=2#top
└─协议─┘ └─认证─┘ └──主机──┘ └端口┘ └──路径──┘└──查询──┘└哈希┘

二、你笔记里的旧 API（legacy，已废弃）

const url = require('url')
const u = url.parse('https://a.com:8080/p?x=1#h')   // 字符串 → 对象
const s = url.format(u)                              // 对象 → 字符串
字段内容（以 https://a.com:8080/p?x=1#h 为例）
protocolhttps:
hosta.com:8080
hostnamea.com
port8080
pathname/p
search?x=1（带问号）
queryx=1（字符串；第二个参数传 true 则变成对象）
hash#h（带井号）
href完整原始地址

⚠️ url.parse / url.format / url.resolve 从 Node 19 起标记为弃用（DEP0169），新代码不建议再用；课本这么写是因为老教材，考场上写没问题，实际项目请用下面的 WHATWG 版。

三、现在推荐的写法：全局 URL（无需 require）

const u = new URL('https://a.com:8080/p?x=1&page=2#h')

u.protocol   // 'https:'
u.hostname   // 'a.com'
u.port       // '8080'
u.pathname   // '/p'
u.search     // '?x=1&page=2'
u.hash       // '#h'
u.origin     // 'https://a.com:8080'

// 取参数（重点）
u.searchParams.get('page')        // '2'
u.searchParams.has('x')           // true
u.searchParams.getAll('tag')      // 同名参数全部取回
u.toString()                      // 拼回字符串

相对地址必须给 base：

new URL('/api/list', 'http://localhost:3000')   // http://localhost:3000/api/list
new URL('/api/list')                            // ❌ 抛 TypeError: Invalid URL

四、服务器里怎么用（实战）

const http = require('http')

http.createServer((req, res) => {
    // req.url 只有 '/api/list?id=1&page=2'，没有域名，所以要给个 base
    const u = new URL(req.url, 'http://' + req.headers.host)

    if (u.pathname === '/api/list') {
        const page = Number(u.searchParams.get('page')) || 1
        const size = Number(u.searchParams.get('size')) || 10
        // ...按 page/size 取数据
    }
})

五、其他相关工具

工具作用备注
decodeURIComponent(s)把 %E5%9B%BE1.jpg 还原成「图1.jpg」中文参数必用
encodeURIComponent(s)反向编码拼查询串、下载文件名时用
querystring.parse(s)查串 → 对象legacy，等价 new URLSearchParams(s)
querystring.stringify(o)对象 → 查串legacy
new URLSearchParams(s)查询串专用解析全局可用，支持 .get/.set/.append/.delete

六、容易遗漏（这个板块最需要补的）

  1. 只学了 parse/format 两个方法，而它们在 Node 19+ 已弃用 —— 至少要知道 new URL() 的存在，否则面试/项目里会显得落后一整代；
  2. 没写「怎么取查询参数」，而这才是服务器里 90% 的使用场景（?page=2&kw=星穹）；
  3. 没写中文/特殊字符的编解码，req.url 里的中文永远是 %E5%9B%BE 形式，不 decodeURIComponent 就拿不到原值；
  4. url.parse(req.url) 得到的是相对路径对象，host 是 null，这点和 new URL(req.url, base) 不同；
  5. search 带 ?、hash 带 # —— 做字符串比较时容易多带一个符号导致匹配不上；
  6. url.parse(u, true) 的第二个参数 true 会把 query 解析成对象，课本大概率会用到，建议补上。
