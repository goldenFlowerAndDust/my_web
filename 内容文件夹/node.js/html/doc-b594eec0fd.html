第七节课 ｜ http 模块：自己搭一个 Web 服务器

数据来源：课堂/第七节课——HTTP模块/第七节课-总结.md · 更新于 2026-11-10

板块定位：Node 从「玩文件」进入「对外提供服务」，理解 req / res 这对东西，是后面 Express 的地基。本板块已有文件：HTTP模块.js（两个服务器：文本响应 + 文件下载）、image/（三层报错截图）

一、重点

  1. 服务器 = 一个一直挂着的进程，监听端口，每来一个请求就执行一次回调。
  2. http.createServer((req, res) => {}) 的等价写法是 server.on('request', cb)。
  3. req 是「请求」：网址、方法、请求头；res 是「响应」：状态码、响应头、正文。
  4. 响应头决定浏览器怎么处理内容：Content-Type 决定「当文本/图片/下载」，Content-Disposition 决定「直接打开还是下载」。
  5. 大文件不要一次读进内存，用 fs.createReadStream().pipe(res) 流式输出。

二、API 速查

对象/方法作用关键点
http.createServer(cb)创建服务器返回 server 实例，此时还没监听
server.listen(port, cb)监听端口端口被占抛 EADDRINUSE
server.close(cb)关闭服务器
req.url请求路径（含 query）用它来做路由分发
req.methodGET / POST …
req.headers请求头对象键名全小写
res.statusCode状态码（属性，不是方法）200 / 404 / 500
res.setHeader(name, value)设置响应头值必须是 ASCII，中文要 encodeURIComponent
res.writeHead(status, headers)一次设置状态码 + 多个头与已 setHeader 的合并
res.write(chunk)写正文（可多次）
res.end(data)结束响应只能调用一次，之后的写入全部无效
fs.createReadStream(p)创建可读流大文件首选
readStream.pipe(res)流对接不用手动 end

三、写法模板

const http = require('http')
const fs = require('fs')
const path = require('path')

const server = http.createServer((req, res) => {
    // 1. 简单路由
    if (req.url === '/' || req.url.startsWith('/?')) {
        res.writeHead(200, { 'Content-Type': 'text/plain; charset=utf-8' })
        return res.end('响应成功')
    }

    // 2. 文件下载
    const filePath = path.join(__dirname, './代码.zip')
    if (!fs.existsSync(filePath)) {
        res.writeHead(404, { 'Content-Type': 'text/plain; charset=utf-8' })
        return res.end('抱歉，文件丢失')
    }

    res.setHeader('Content-Type', 'application/octet-stream')
    res.setHeader('Content-Disposition',
        `attachment; filename="download.zip"; filename*=UTF-8''\${encodeURIComponent('代码.zip')}`)

    const stream = fs.createReadStream(filePath)
    stream.on('error', () => res.end('读取失败'))   // 流也要兜底，否则进程可能崩
    stream.pipe(res)
})

server.listen(3000, () => console.log('http://localhost:3000'))

四、你笔记里做得对的地方

  • createServer 默认就是 request 事件、要监听多个事件时才需要 server.on —— 这条理解得很准；
  • 列出 request / connection / close / error / upgrade 五类事件，比课本全；
  • res.statusCode 是属性不是方法、res.end() 只能一次、分支里记得 return —— 三个都是新手最容易翻车的地方，你全记下了；
  • Content-Disposition 用了 filename*=UTF-8'' 的 RFC 5987 写法，中文文件名才不会乱码，这段已经超出课本要求；
  • 三层截图（第一次失败、路径问题失败、当前网页下载失败）说明你是靠报错倒推学过来的，这个习惯很好。

五、容易遗漏 / 建议补充

1. res.write 可以多次，res.end 只能一次

你写「一个服务器，只能有一个 .end()」——更准确的是「一个响应只能 end 一次」。服务器可以有无数个请求、无数次 end。

2. 端口占用的处理

server.on('error', (err) => {
    if (err.code === 'EADDRINUSE') console.log('端口被占用，换个端口或用 taskkill 结束旧进程')
})

开发时最常见的就是「上一个 node 没关，3000 还被占着」。

3. 请求体（POST 数据）要自己收集

req 是流，不会一次性给你 body：

let body = ''
req.on('data', chunk => body += chunk)
req.on('end', () => { console.log('收到：', body) })

4. 路由还没有，先用 req.url 判断

你现在对所有请求返回同一个东西。想区分页面/接口，就得 if (req.url === '/data') ...。路由表、中间件就是后面的 Express 帮你做的事。

5. 跨域（CORS）

前端 file:// 或不同端口访问时会被浏览器拦，服务端要放行：

res.setHeader('Access-Control-Allow-Origin', '*')

第九节课就是被这个卡过的地方。

6. 大文件与断点续传（进阶，知道即可）

  • 普通下载用 pipe 就够；
  • 支持断点续传要读 req.headers.range，回 206 Partial Content + Content-Range；
  • 需要显示下载进度条时可以设 Content-Length。

7. 一些细节

  • localhost:250 这种低位端口在 Linux/macOS 需要管理员权限（Windows 一般不用）；
  • setHeader 的值不能含中文，文件名要用 encodeURIComponent；
  • 301/302 + Location 才会跳转，这一点你笔记里写对了；
  • 用 path.join(__dirname, ...) 拼路径，别用相对当前目录的 ./，否则换个启动目录就 404。
