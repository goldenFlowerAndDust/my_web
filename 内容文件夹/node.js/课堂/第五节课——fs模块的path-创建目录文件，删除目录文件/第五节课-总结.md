# 第五节课 ｜ fs + path：建目录、批量建文件、改名、删除

> 板块定位：从「读写一个文件」升级到「管理一堆文件」，并第一次用 `fs.promises` + `async/await` 串流程。
> 本板块已有文件：`创建目录.js`、`创建多个后缀不同文件.js`、`读取后缀文件-删除-修改文件.js`、`2026-10-20——复习/创建目录以及文件.js`、`测试/`

---

## 一、重点

1. **目录 ≠ 文件**：`mkdir` 建目录，`writeFile` 建文件，`rm` 删目录，`unlink` 删文件。
2. `mkdir` 默认**不递归**：父目录不存在直接报错，必须 `{ recursive: true }`。
3. `readdir` 拿到的是**文件名数组**，不含路径，后续操作要自己 `path.join` 拼回去。
4. 改后缀 = `rename`（同一目录内改名），不是「新建再删掉」。
5. **`fs.promises` 是同一套 API 的 Promise 版**，能用 `await`，不用嵌套回调。

---

## 二、API 速查

| 操作 | 回调版 | Promise 版 | 关键参数 |
|---|---|---|---|
| 建目录 | `fs.mkdir(p, {recursive:true}, cb)` | `await fs.promises.mkdir(p, {recursive:true})` | `recursive`、`mode`（Windows 无效） |
| 读目录 | `fs.readdir(p, cb)` | `await fs.promises.readdir(p)` | `{withFileTypes:true}` 可直接拿到类型 |
| 重命名/移动 | `fs.rename(old, new, cb)` | `await fs.promises.rename(old, new)` | 跨盘会失败（EXDEV） |
| 删文件 | `fs.unlink(p, cb)` | `await fs.promises.unlink(p)` | |
| 删空目录 | `fs.rmdir(p, cb)` | `await fs.promises.rmdir(p)` | 有内容会报错，**已不推荐** |
| 删目录/递归 | `fs.rm(p, {recursive:true, force:true}, cb)` | `await fs.promises.rm(p, {recursive:true})` | `force` = 不存在也不报错 |
| 文件是否存在 | `fs.existsSync(p)` | — | 只有同步版 |

**path 模块**（纯字符串计算，不碰磁盘）：

| 方法 | 作用 | 例子 |
|---|---|---|
| `path.join(a, b)` | 拼路径，自动处理分隔符 | `path.join('./测试','1.txt')` |
| `path.resolve(a, b)` | 拼成**绝对路径**（依赖 `process.cwd()`） | |
| `path.basename(p, ext)` | 取文件名，可去掉后缀 | `basename('1.docx','.docx')` → `1` |
| `path.extname(p)` | 取后缀（含点） | `extname('1.docx')` → `.docx` |
| `path.dirname(p)` | 取目录部分 | |
| `path.parse(p)` | 拆成 `{root,dir,base,ext,name}` | 一次拿全 |

## 三、写法模板（Promise 版，推荐）

```js
const fs = require('fs')
const path = require('path')

async function main() {
    try {
        await fs.promises.mkdir('./测试', { recursive: true })

        // 批量建文件（串行）
        for (let i = 1; i <= 3; i++) {
            await fs.promises.writeFile(`./测试/${i}.txt`, 'hello')
        }

        // 读目录 → 改后缀
        const files = await fs.promises.readdir('./测试')
        for (const f of files) {
            if (path.extname(f) === '.txt') {
                await fs.promises.rename(
                    path.join('./测试', f),
                    path.join('./测试', path.basename(f, '.txt') + '.md')
                )
            }
        }

        // 删除整个目录（含内容）
        await fs.promises.rm('./测试', { recursive: true, force: true })
    } catch (err) {
        console.error('出错了：', err.message)
    }
}
main()
```

## 四、你笔记里做得对的地方

- `mkdir` 的三个参数、`recursive` 的作用、回调第二个参数 `path` 的含义（返回第一个被创建的目录、类型与传入一致）—— 这段写得很细，很多人根本不知道有第二个参数；
- `rm` 的 `recursive` / `force` 两个选项，以及 `rmdir` 只能删空目录，都对；
- `2026-10-20——复习` 里已经用 `fs.promises` + `async/await` 把「建 → 改 → 删」串成一个流程，方向完全正确；
- 自己总结的「async 内部才是异步、await 必须跟 Promise」也是准确的。

## 五、容易遗漏 / 建议修正

### 1. 复习文件里 `Modfiy()` 有双重替换的 bug

```js
const newname = fixs.replace(ext, extMap[ext]).replace(oldn, extMap[ext].replace('.', ''))
```

第一步 `.replace('.css', '.md')` 已经改好后缀，第二步 `replace('css', 'md')` 会把**文件名里出现的 css** 也换掉：

```text
第1个css文件.css  ->  第1个css文件.md  ->  第1个md文件.md   ❌
```

只留一步就够：

```js
const newname = path.basename(fixs, ext) + extMap[ext]
```

### 2. `path.join` 和 `path.resolve` 别混用

- `join` 只是拼字符串，结果仍是相对路径；
- `resolve` 从 `process.cwd()` 出发算成绝对路径 —— **同一个脚本在不同目录启动，resolve 结果不同**。

想稳定指向「脚本所在目录」，用 `__dirname`：

```js
const dir = path.join(__dirname, '测试')
```

### 3. `readdir` 的返回值不含路径

`files` 里是 `'1.txt'` 这种纯文件名，直接 `fs.unlink(f)` 会在**当前工作目录**找，而不是 `./测试` 下找。必须 `path.join('./测试', f)` —— 你在 `读取后缀文件-删除-修改文件.js` 里做对了，保持这个习惯。

### 4. 可以补充的 API 细节

- `path.extname('.gitignore')` 返回 `''`，`path.extname('a.tar.gz')` 只返回 `.gz`；
- `fs.rmdir` 带 `recursive` 已废弃（Node 16 起建议 `fs.rm`），复习文件里的 `fs.promises.rmdir('./测试删除')` 会出弃用警告；
- `rename` 在目标文件已存在时会**直接覆盖**，且文件被别的程序占用时抛 `EPERM`；
- `readdir(p, { withFileTypes: true })` 能直接区分文件/文件夹（`d.isDirectory()`），比事后 `stat` 快；
- 批量建 100 个文件时，`for + await` 是**串行**（一个等一个），改成 `Promise.all([...])` 才并发。

### 5. 目录里残留的 `测试/`

`测试/` 下还有 12 个文件（`1.docx`、`1.pptx`…），说明最后一次删除没跑成功或没跑。跑脚本前先确认工作目录，这类「删了没删掉」的问题九成是 `cwd` 不对。
