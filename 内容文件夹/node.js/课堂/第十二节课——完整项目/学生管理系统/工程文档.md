| 功能 | 用户操作 | 背后发生了什么 |

## 二、架构与数据流

### 2.1 分层

```
浏览器
 ├─ index.html   结构
 ├─ style.css    外观
 └─ app.js       fetch ─┐
                        │ HTTP + JSON
Express 服务（server.js + db.js）
 ├─ 静态托管      ← / 、/style.css 、/app.js
 ├─ 路由          ← /api/students
 ├─ 校验          ← validate()
 └─ 连接池        ← pool.query()
                        │ SQL
MySQL（student_app.students）
```

### 2.2 一次「添加」的完整时序

```
1. 用户填表单，点「添加」
2. app.js 阻止表单默认提交（e.preventDefault）
3. 组装 body = { sno, name, gender, age, class_name }
4. fetch('/api/students', { method: 'POST', headers: {'Content-Type':'application/json'}, body: JSON.stringify(body) })
5. server.js：express.json() 解析 body → req.body
6. validate(req.body) 校验 → 不通过直接 400
7. pool.query('INSERT ...', [...]) → MySQL 写入
8. res.status(201).json({ id, message })
9. app.js 收到成功 → form.reset() → load() 重新拉列表
10. 页面刷新出新记录
```

## 四、数据库设计

### 4.1 表结构 `student_app.students`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INT UNSIGNED | PK, AUTO_INCREMENT | 主键，前端用不到但接口要用 |
| `sno` | VARCHAR(20) | NOT NULL, **UNIQUE** | 学号，唯一 → 重复插入会报 `ER_DUP_ENTRY` |
| `name` | VARCHAR(50) | NOT NULL | 姓名 |
| `gender` | ENUM('男','女') | NOT NULL DEFAULT '男' | 值域限制，插入非法值会被拒 |
| `age` | TINYINT UNSIGNED | NULL | 允许空（未知年龄） |
| `class_name` | VARCHAR(50) | NULL | 班级 |
| `created_at` | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | 插入时自动填充，前端展示用 |

### 4.2 几个设计决定，为什么这么做

| 决定 | 原因 |
|---|---|
| 用自增 `id` 做主键，而不是 `sno` | 学号可能录错要改；主键一旦被业务字段占用，改起来会牵连外键 |
| `sno` 加 UNIQUE | 业务上不允许重复；数据库层兜底，比只在 JS 里判重可靠 |
| `gender` 用 ENUM | 取值只有两个，写错直接报错，不必在代码里反复校验 |
| `created_at` 用 DEFAULT | 不用前端传，也不怕忘 |
| 表用 InnoDB | 支持事务、行锁，是默认选择 |

## 五、接口文档

### 5.0 统一约定

| 约定 | 内容 |
|---|---|
| 数据格式 | 请求/响应都是 `application/json; charset=utf-8` |
| 成功响应 | 2xx + JSON 数据 |
| 失败响应 | 4xx/5xx + `{ "error": "人话描述" }` |
| 字符集 | 全链路 UTF-8（库 utf8mb4） |
| 认证 | 暂无（学习阶段） |

### 5.1 列表 + 搜索 + 分页

```
GET /api/students?kw=软件&page=1&size=5
```

| 参数 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `kw` | 否 | 空 | 模糊匹配 学号 / 姓名 / 班级 |
| `page` | 否 | 1 | 页码，从 1 开始 |
| `size` | 否 | 5 | 每页条数，最大 50 |

成功响应：

```json
{
  "list": [
    { "id": 6, "sno": "2026006", "name": "周八", "gender": "女", "age": 19, "class_name": "软件1班", "created_at": "2026-11-20 10:22:17" }
  ],
  "total": 2,
  "page": 1,
  "size": 5,
  "pages": 1
}
```

> `pages` 由后端算好，前端直接用来禁用「下一页」按钮。

### 5.2 新增

```
POST /api/students
Content-Type: application/json

{ "sno": "2026999", "name": "新来的", "gender": "女", "age": 18, "class_name": "测试班" }
```

| 响应 | 说明 |
|---|---|
| `201 { "id": 9, "message": "添加成功" }` | 成功 |
| `400 { "error": "学号不能为空" }` | 校验失败 |
| `400 { "error": "性别只能是 男/女" }` | 枚举非法 |
| `400 { "error": "学号已存在" }` | 唯一索引冲突 |

### 5.3 修改

```
PUT /api/students/:id
```

请求体同新增。响应：`200 { "message": "修改成功" }` / `404 { "error": "找不到这个学生" }`。

### 5.4 删除

```
DELETE /api/students/:id
```

响应：`200 { "message": "删除成功" }` / `404 { "error": "找不到这个学生" }`。

### 5.5 错误码对照

| 状态码 | 什么时候 | 前端怎么处理 |
|---|---|---|
| 200 | 查询/修改/删除成功 | 刷新列表 |
| 201 | 新增成功 | 清空表单 + 刷新 |
| 400 | 参数不合法 | 显示 `error` 文案 |
| 404 | id 不存在 / 接口路径错 | 同上 |
| 500 | 服务端异常（如数据库连不上） | 同上，需看服务端控制台 |

## 六、前端设计

### 6.1 状态：页面只有 5 个变量

```js
const state = {
    page: 1,          // 当前页
    size: 5,          // 每页几条
    kw: '',           // 搜索关键字
    pages: 1,         // 总页数（后端算的）
    editingId: null,  // null=新增；有数字=正在编辑这条
    list: [],         // 当前页数据（编辑时回填表单）
}
```

**所有界面变化都由这 5 个变量推导**：改 `page` 再 `load()`，表格就换了页；改 `editingId`，表单就切换形态。这叫“状态驱动”，比到处 `innerHTML` 好维护。

### 6.2 三个核心函数

| 函数 | 位置 | 职责 |
|---|---|---|
| `api(url, options)` | app.js:46 | 统一发请求：自动加 JSON 头、解析 JSON、把 `error` 抛成异常 |
| `load()` | app.js:99 | 按当前 state 拉数据 → 渲染表格 + 分页信息 |
| `renderRows(list)` | app.js:57 | 数组 → `<tr>` 字符串，空数据给提示 |

### 6.3 新增 / 编辑共用一个表单

```
editingId === null  →  表单是“新增”，按钮文字「添加」
editingId === 9     →  表单是“编辑”，按钮文字「保存修改」
提交时看 editingId 决定 POST 还是 PUT
```

这是最常见的省代码手法：**一个表单 + 一个标志位**，比写两个表单干净。

### 6.4 为什么用事件委托

```js
tbody.addEventListener('click', e => { const btn = e.target.closest('button') ... })
```

表格行是动态生成的。如果每次渲染都给每个按钮绑一次监听，旧的监听不会自动销毁，越绑越多。**绑在父元素上、靠 `closest()` 判断点的是谁**，一次绑定终身有效。

### 6.5 防 XSS

```js
const esc = s => String(s ?? '').replace(/[&<>"']/g, c => ...)
```

渲染时用 `esc()` 转义。虽然本项目数据来自数据库、相对可信，但**这个习惯必须从现在养成**——一旦以后允许用户自己填内容，不转义就是漏洞。

## 七、工程化实践

| 实践 | 在本项目里的样子 | 为什么重要 |
|---|---|---|
| **配置与代码分离** | `.env` + `process.env`，代码里零密码 | 换环境不用改代码；密码不进 Git |
| **忽略敏感文件** | `.gitignore` 里有 `.env`、`node_modules/` | 一次失误就能把密码传上 GitHub |
| **依赖只装一次** | 根目录 `node_modules`，示例通过「向上查找」共用 | 子目录不需要再装一遍包 |
| **连接池** | `db.js` 里 `createPool` | 并发请求复用连接，不反复握手 |
| **参数化查询** | 所有 SQL 都用 `?` | 防 SQL 注入 |
| **统一错误处理** | `server.js:142` 的 4 参数中间件 | 避免每个接口都写一遍 try/catch 的返回 |
| **REST 语义** | GET 查、POST 增、PUT 改、DELETE 删 | 别人（和未来的你）一看就懂 |
| **一键启动** | `示例\启动.cmd` | 不用记命令，也不用担心忘参数 |

## 十、验收标准（能答上来才算真会）

### 10.1 概念题

| # | 问题 | 参考答案要点 |
|---|---|---|
| 1 | 浏览器为什么不直接连 MySQL？ | 浏览器没有 MySQL 驱动/端口协议，也没有账号；必须由服务端代理 |
| 2 | 为什么 `/api/students` 不写 `http://localhost:3100`？ | 同源，相对路径自动跟随页面所在服务器 |
| 3 | `fetch` 为什么要两次 `await`？ | 第一次等响应头，第二次 `res.json()` 读 body 流 |
| 4 | `express.json()` 是干什么的？不写会怎样？ | 把 JSON 请求体解析到 `req.body`；不写 `req.body` 是 undefined |
| 5 | 为什么 SQL 要用 `?` 而不是拼字符串？ | 防 SQL 注入，驱动会转义 |
| 6 | `LIMIT 5 OFFSET 5` 取的是第几页？ | 第 2 页（page=2, size=5） |
| 7 | 为什么 `sno` 要有 UNIQUE？ | 业务不允许重复；数据库兜底，比 JS 判重可靠 |
| 8 | 编辑和新增为什么能共用一个表单？ | 用 `editingId` 区分，提交时决定 POST/PUT |
| 9 | 为什么按钮事件绑在 `tbody` 上？ | 行是动态生成的，事件委托避免重复绑定 |
| 10 | 报 `using password: NO` 是什么意思？ | 没给密码（`.env` 没加载），不是密码错 |
| 11 | 500 和 400 的区别？ | 500 是服务端出错（代码/数据库），400 是请求方参数不对 |
| 12 | 为什么 `.env` 要写进 `.gitignore`？ | 里面是密码，提交等于公开泄露 |

## 十一、调试方法（三层定位）

```
现象出在哪一层？

① 页面没反应 / 样式没生效
   → F12 Console 有没有红色报错
   → Elements 看元素在不在、class 对不对

② 请求发出去了但结果不对
   → F12 Network 看：状态码、请求 URL、请求体、响应体
   → 状态 404 = 路径/服务器错；400 = 参数；500 = 服务端

③ 服务端报错
   → 看运行终端里的 console.error
   → 对照 README 的错误表（ECONNREFUSED / ER_DUP_ENTRY / ...）

④ 数据库里没数据
   → Navicat/WebStorm 里直接 SELECT 一次，确认到底写没写进去
```

### 三个高频错误

| 错误 | 真正原因 | 一句话排查 |
|---|---|---|
| 页面 404，但服务端有路由 | 页面不是这个服务托管的（file:// 或 WebStorm 63342） | 看地址栏端口是不是服务端口 |
| `using password: NO` | 启动时没带 `--env-file=.env` | 看启动命令 |
| 新增后列表没变 | 前端没重新 `load()` | 看提交成功分支里有没有调 load |
