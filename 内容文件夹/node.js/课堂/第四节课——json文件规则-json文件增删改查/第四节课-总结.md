# 第四节课 ｜ JSON 文件规则 + 增删改查（CRUD）

> 板块定位：把 JSON 当成「最简单的数据库」，练会 `读 → parse → 改 → stringify → 覆盖写` 这条链路。
> 本板块已有文件：`JSON批量读取-增删改查.js`、`测试文件读写.js`、`注意事项.txt`、`order.json`、`new_order.json`

---

## 一、重点

1. **JSON 是字符串格式，不是 JavaScript 对象**。要操作先 `JSON.parse()` 转成数组/对象，改完再 `JSON.stringify()` 转回字符串才能写文件。
2. **Node 没有「直接写对象到文件」的 API**，必须序列化成字符串（Python 的 `json.dump` 没有对应物）。
3. **写入是覆盖式的**：`writeFile` 一次把整个文件重写，所以「改一条数据」= 读出全部 → 改 → 整体写回。
4. **异步顺序不保证**：`writeFile` 还没落地就去 `readFile`，会读到旧内容或报错 —— 这就是你笔记里的「抢跑」。

---

## 二、JSON 语法铁律（考试/报错高频）

| 规则 | 反例 | 正解 |
|---|---|---|
| 不允许注释 | `// 注释` | 删掉，或另写说明文件 |
| 不允许单引号 | `{'name': '苹果'}` | `{"name": "苹果"}` |
| 键必须双引号 | `{name: 1}` | `{"name": 1}` |
| 最后一个元素后不能有逗号 | `[1, 2,]` | `[1, 2]` |
| 不允许 undefined / 函数 | `{"a": undefined}` | 不写这个键 |
| NaN / Infinity 不合法 | `{"n": NaN}` | 用字符串或数字 |

---

## 三、API 速查

| 方法 | 方向 | 说明 |
|---|---|---|
| `JSON.parse(str)` | 字符串 → 对象 | 格式不对直接抛 `SyntaxError`，**要 try/catch** |
| `JSON.parse(str, reviver)` | 同上 | 第二个参数可对每个键值做转换（反序列化时改值） |
| `JSON.stringify(obj)` | 对象 → 字符串 | 默认无缩进，一行 |
| `JSON.stringify(obj, null, 2)` | 同上 | 第三参数 2 = 缩进 2 空格，便于人看 |
| `JSON.stringify(obj, replacer, 2)` | 同上 | 第二参数过滤字段（白名单数组 / 黑名单函数） |
| `fs.writeFile(路径, 字符串, ...)` | 落盘 | 覆盖写；内容必须是字符串或 Buffer |

**replacer 的两种写法**：

| 传数组 | 传函数 |
|---|---|
| 白名单：只有数组里列出的键会保留 | 逐层递归调用 `(key, value)`，返回 `undefined` 表示丢弃 |
| `JSON.stringify(o, ['name','price'], 2)` | `JSON.stringify(o, (k, v) => k === 'price' ? undefined : v, 2)` |

## 四、标准写法（增删改查）

```js
const fs = require('fs')
const FILE = './order.json'

// 读
const list = JSON.parse(fs.readFileSync(FILE, 'utf-8'))

// 增
list.push({ name: '草莓', price: 60, quantity: 50, date: '2006-09-09' })

// 删：按条件过滤比 delete 安全
const next = list.filter(item => item.name !== '香蕉')

// 改
const item = list.find(i => i.name === '苹果')
item.price = 20

// 写回（覆盖）
fs.writeFileSync(FILE, JSON.stringify(list, null, 2), 'utf-8')
```

> 处理函数用 `async/await` 或 `try/catch` 包住，别让一个格式错误把整个程序崩掉。

## 六、容易遗漏 / 建议补充（部分实测过）

### 1. `JSON.stringify` 的几个坑

```text
JSON.stringify(undefined)        -> undefined（不是字符串！写文件会报错）
JSON.stringify({ f: () => 1 })   -> "{}"（函数被丢掉）
JSON.stringify({ n: NaN })       -> '{"n":null}'
JSON.stringify(循环引用对象)     -> 抛 TypeError: Converting circular structure to JSON
```

### 2. 你那个 `key === '2'` 的 replacer，效果和注释不一样

```js
JSON.stringify([{n:1},{n:2},{n:3}], (k, v) => k === '2' ? undefined : v)
// 实际结果：'[{"n":1},{"n":2},null]'  ← 不是删掉，是变成 null
```

数组下标被拦截时，`JSON.stringify` 会用 `null` 占位（长度不变）。真要删元素，用 `splice` / `filter`。

### 3. `JSON.parse` 没有 try/catch

`JSON批量读取-增删改查.js` 里三处 `JSON.parse` 都没包 `try/catch`。文件被手改坏一个逗号，程序直接崩。规范写法：

```js
let json
try { json = JSON.parse(data) } catch (e) { return console.error('JSON 格式错误：', e.message) }
```

### 4. 三层回调嵌套 = 回调地狱

你现在的代码是 `readFile → writeFile → readFile → writeFile` 四层嵌套，还差点因为顺序问题踩坑。这正是第六节课 `async/await` 要解决的问题，提前知道方向就好。

### 5. 覆盖写的安全问题

你担心的「覆盖后无法溯源」可以用两个办法兜底：

```js
// 方案 A：先备份
fs.copyFileSync('./order.json', './order.json.bak')

// 方案 B：写临时文件再改名（原子替换，断电也不会写出半个文件）
fs.writeFileSync('./order.tmp', JSON.stringify(list, null, 2))
fs.renameSync('./order.tmp', './order.json')
```

### 6. 字段名不统一

`order.json` 用 `date`，而第二节课的 `shopp.js` 里写的是 `data`，`packdocut.json` 里又是 `imag`。字段名统一能省掉大量「为什么是 undefined」的排查。
