## 一、核心知识点提炼（按语言分类）

### 1. Python —— 语法骨架与数据模型

#### 1.1 变量、字面量与类型系统
- **字面量即数据本身**（`10`、`3.14`、`"abc"`、`True`、`None`），变量是"容器"而非"值"，本质是**指向堆中对象的引用**。
- **Python 无隐式类型转换**，这是与 JS/MySQL 最根本的分水岭：`"5" + 5` 直接 `TypeError`。这条规则穿透了后续所有知识点（运算符、容器、格式化、文件写入）。
- **`bool` 是 `int` 的子类**：`True == 1`、`False == 0`，因此布尔可以参与算术；但 `==` 是"值比较"，`is` 才是"身份（内存地址）比较"。
- **类型检查双通道**：`type(x)` 返回类型本身，`isinstance(x, T)` 返回布尔（支持元组多类型判断），且后者尊重继承关系——这是唯一"尊重继承"的判断方式。

#### 1.2 运算符的"语义三分"
笔记中最有价值的部分是把运算符在 **Python / JavaScript / MySQL** 三方做了对照：

| 运算符 | Python | JS / MySQL | 关键差异 |
|---|---|---|---|
| `/` | 真除，恒为 float | 同 | 一致 |
| `//` | **向下取整**（`-5//2 == -3`） | `Math.trunc()` **向零取整** | 商的方向不同 |
| `%` | 余数符号**跟除数**走 | 余数符号**跟被除数**走 | 由商的方向差异导致 |
| `*`（str） | `'ab'*3 → 'ababab'` | 需 `.repeat()` | Python 原生 |
| `**` | 幂 | `Math.pow` | 一致 |

> 精髓：**`//` 的方向决定了 `%` 的符号**，二者是同一套整除定义的两种投影。正数场景三者一致，负数场景必分叉。

#### 1.3 流程控制
- `if / elif / else`、`while / else`、`for / else`：**`else` 仅在"循环未被 `break` 中断"时执行**，这是 Python 独有的"循环正常完成"语义钩子。
- **`match-case`**：结构性模式匹配，本身即隐式 `break`（无穿透），多条件用 `|` 合并，支持 `case x if x > 0` 守卫。
- **`for` 只有一种形式** `for x in iterable`，与 JS 的 `for / for-in / for-of` 完全对应关系被放大为"迭代协议"的统一抽象；`range()` 只是产出"整数序列"的一类可迭代对象。
- **Python 无块级作用域**（`if`/`for` 不建作用域），这与 ES6 `let/const` 的块级作用域形成鲜明对比。

#### 1.4 五大容器及其"性格"

| 容器 | 有序 | 可变 | 可重复 | 可哈希 | 典型场景 |
|---|---|---|---|---|---|
| `list []` | ✅ | ✅ | ✅ | ❌ | 通用序列、批量数据 |
| `tuple ()` | ✅ | ❌ | ✅ | ✅（元素可哈希时） | 定长记录、字典键、函数多返回值 |
| `dict {}` | ✅（3.7+ 插入序） | ✅ | 键不可重复 | 键必须可哈希 | 映射、结构化数据 |
| `set {}`/`set()` | ❌ | ✅ | ❌ | 元素必须可哈希 | 去重、集合运算 |
| `str ""` | ✅ | ❌ | ✅ | ✅ | 文本 |

- **切片 `[start:stop:step]`**：解析顺序应是 **①先按公式 `len+负数索引` 统一正向化 → ②判断方向与区间是否冲突（冲突即空） → ③左闭右开取值**。三者可统一为一条：`step>0` 时 `start<stop` 有效，`step<0` 时 `start>stop` 有效。
- **解包**：`a, b = b, a` 的本质是 **右侧先组包成元组 → 左侧再解包**；`*` 在左侧是"收集剩余成 list"，在右侧是"展开容器"——**同一符号，位置决定语义**。
- **`*` 在解包中的定位规则**：先分配非 `*` 变量（`*` 在左→右侧变量由右向左取；`*` 在中间→两侧分别向左向右取），最后分配 `*`。

#### 1.5 推导式与"惰性"
- **四种推导式**：`[x for ...]`（list）、`{k:v for ...}`（dict）、`{x for ...}`（set）、`(x for ...)`（generator，**惰性**）。
- **没有元组推导式** —— `(x for x in ...)` 是生成器表达式，需 `tuple(...)` 才得到元组，这是初学者高频误区。
- **生成器与推导式的分界线是"求值时点"**：推导式"立即生产全部"，生成器"按需逐个产出"。

#### 1.6 字符串
- 三种定义方式（单/双/三引号）；**外层引号决定边界，内层不能出现相同引号**，否则提前截断。
- **`f-string` 是格式化最优解**（可读性、性能、能内嵌表达式），但**大括号内不允许反斜杠**、**不允许嵌套 f-string**——这是它相对 JS 模板字符串的两处限制。
- `+` 拼接不隐式转换（TypeError），`%s` 与 `str.format` 属于"历史写法"，`f-string` 是当前最佳实践。

### 2. Python —— 函数体系（本项目最核心的能力区）

#### 2.1 参数系统的"五层优先级"
```
位置参数 > 默认参数 > *args > 强制关键字 > **kwargs
```
- 定义顺序约束：默认参数必须在非默认参数之后；`*` 之后的形参自动转为"强制关键字"；`**` 必须最后且唯一。
- 调用顺序约束：关键字参数必须在位置参数之后；同一形参不得被重复赋值（`SyntaxError` vs `TypeError` 的分界点：**调用语法错 → `SyntaxError`；调用值语义错 → `TypeError`**）。
- `*args` 收集"多余位置参数"→ tuple；`**kwargs` 收集"多余关键字参数"→ dict，且 **key 强制为 str**（硬性规则，比"可哈希"更严）。

#### 2.2 作用域与 LEGB
- **LEGB 查找**：`Local → Enclosing → Global → Built-in`。
- 函数内部**读**全局变量无需声明；**写**全局需 `global`；嵌套函数**写**外层变量需 `nonlocal`。否则一律**新建局部变量**（遮蔽而非修改）。
- 这是"最易踩坑"的性质之一，尤其对从 JS 转来的人——JS 中闭包修改外层变量无需关键字。

#### 2.3 递归与栈
- 递归的公式：**终止条件 + 递推关系 + 栈帧模型**。
- 你的笔记把递归过程拆成了 **"入栈挂起（列函数）→ 出栈计算（从栈顶往回算）→ 逐层返回并销毁栈帧"** 三段，并配上阶乘与数位求和的 traced 示例——这是教科书级别的理解深度。
- Python 默认递归上限 1000 次（`sys.getrecursionlimit()` 可调）。

#### 2.4 高阶函数与函数对象
- **函数是一等公民**：`map` / `filter` / `sorted(key=...)` / `lambda` 全部建立在此。
- **三者返回值差异是易错核心**：
  - `sorted` → 新 list（不改原容器）
  - `list.sort` → 原地（返回 None）
  - `filter` / `map` → **迭代器**（需 `list(...)` 物化才能真正使用）
- `lambda` 只能写单表达式，**不能写语句**（`try` / `if-elif-else` / `for`）；复杂逻辑必须回落 `def`。

### 3. Python —— 异常处理（防御性编程的完整体系）

#### 3.1 完整语法骨架
```
try ──▶ 可能出错的少数几行
except 具体异常 as e ──▶ 分类处理 + 记录原始错误
else ──▶ 无异常时的正常逻辑（与 try 分离）
finally ──▶ 资源清理（无条件执行，且禁止 return）
```

#### 3.2 关键判断（笔记中提炼准确的知识）
- **`SyntaxError` 无法被运行时 `except` 捕获** —— 它在"解释器读代码阶段"就抛出，`try` 尚未诞生。
- **裸 `except:` 会吞掉 `KeyboardInterrupt` / `SystemExit`** —— 程序"该退不退"，因此规范必须写具体异常或 `except Exception`。
- **异常传递** = 栈的"请求未响应逐层上传"，直到最外层；未捕获则进程终止。
- **`raise X from e`** —— 保留原始异常链，输出两份 traceback，便于定位根因。
- **自定义异常**：`class MyError(Exception): pass`，实际项目中用于业务语义分层。
- **异常层级树**（笔记中完整画出）：`BaseException → Exception → (ValueError / TypeError / KeyError / IndexError / OSError ...)`，理解树形结构是"精准捕获"的前提。

#### 3.3 两大误区
1. **把整个主程序塞进 `try`** —— 掩盖真实的错误位置，不利调试。
2. **在 `finally` 中 `return`** —— 会覆盖本应抛出的异常，静默吞错。

### 4. Python —— 文件 IO 与编码

- **`open(file, mode, encoding)`** 返回"文件对象"（本质是"管道/遥控器"，内部含句柄、光标、模式、编码）。
- **模式矩阵**：
  - `r/rt/rb` 只读，文件必须存在 → `FileNotFoundError`；`w/…` 覆盖写（文件不存在则建）；`a/…` 追加写；
  - `+` 加读写；`b` 二进制；`t` 文本。
- **`w` / `r+` / `a` 的光标起点不同**：`w` 清空+开头、`r+` 开头（覆盖写）、`a` 末尾。
- **`r+` 想读回刚写的内容必须 `seek(0)`** —— 因为写完后光标在写结束处。
- **`t` 与 `b` 的数据类型不兼容**：文本模式 `write` 必须 str，二进制必须 bytes，否则 `TypeError`。
- **编码三定律**：`rb` 拿到 bytes 不自动解码；文本模式自动用操作系统默认解码器（Windows=GBK，Linux=UTF-8）；**跨平台一致的最佳实践是显式 `encoding='utf-8'`**，否则必然 `UnicodeDecodeError`。
- **`with` 语句**是资源管理的唯一正确姿势（异常也能保证 `close()`），等价于隐式 `try-finally`。

### 5. Python —— 模块与包

- **模块 = `.py` 文件**，包 = 含 `__init__.py` 的目录（命名空间包 3.3+ 可省，但常规项目仍应保留）。
- **导入三种姿势**：`import m`（`m.f()`）/ `from m import f`（`f()`）/ `from m import *`（污染命名空间，仅受 `__all__` 约束）。
- **`as` 重命名**：当前文件生效，不改变原模块名。
- **`sys.path` 就是 import 的搜索顺序**：`sys.path[0]`（脚本目录）→ `PYTHONPATH` + 手动 append → 标准库 → 找不到报错。
- **`if __name__ == "__main__":`** —— 模块既能被导入、又能独立运行的开关，也是防"导入即执行"的安全阀。
- **`__all__`** 只对 `from X import *` 生效，不影响 `import X` 和 `from X import 具体名`。

### 6. Python —— 面向对象（本项目深度最高的模块）

#### 6.1 三件套的内存本质
- **`__dict__`**：每个对象/类的"属性字典"。实例的 `__dict__` 存实例属性，类的 `__dict__` 存类属性 + 方法。
- **`__class__`**：实例 → 类 的引用（存的是类对象地址）。
- **`__bases__`**：类 → 父类 的引用（继承关系的入口）。
- **属性查找链**：`实例.__dict__ → 类.__dict__ → 父类.__dict__ → … → object`；**方法查找链跳过实例层**（方法通常不在实例上）。
- **封装的技术基础**：每个对象拥有独立的 `__dict__`，修改互不影响 → **多态的技术基础**：每个类的 `__dict__` 相互独立，同名方法可有不同实现。

#### 6.2 `__init__` 的真实身份
- **不是"构造函数"**，而是"初始化方法"。真正的创建发生在 `__new__`（返回空白实例），`__init__` 只是给这个空白实例的 `__dict__` 里塞键值对。
- `self.属性 = 值` 等价于 `self.__dict__['属性'] = 值`。
- `self` 就是"将来被创建出来的那个实例"，调用时 Python 自动传入。

#### 6.3 实例属性 vs 类属性（最高频混淆）
- **实例属性**：`self.x = ...`（类内 `__init__`）或 `obj.x = ...`（类外），存实例 `__dict__`。
- **类属性**：类内方法外 `x = ...`，或 `类名.x = ...` 类外声明，存类 `__dict__`，全体实例共享。
- **`obj.类属性 = 值` 只是在 `obj.__dict__` 上"新建"同名属性覆盖**，**不修改类属性**——这就是"修改类属性影响所有实例，但通过实例修改只影响自己"的底层解释。

#### 6.4 魔法方法与运算符重载
- **`__str__`（面向人）/ `__repr__`（面向开发者）** —— `print` 走 `__str__`，交互式环境/`repr()` 走 `__repr__`。
- **`__add__`** 等算术魔法方法：**固定两参 `(self, other)`，链式运算每次都产生"临时新对象"**，中间对象一旦无引用立即被 GC（触发 `__del__`）。
- **比较类魔法方法（`__eq__`/`__lt__`/…）与链式比较**：`a == b == c` 会被解释为 `a == b and b == c`，两次两两重载调用。
- **铁律**：无法处理 `other` 类型时必须 `return NotImplemented`（**不是抛 `NotImplementedError`！**），给右侧对象的反向方法（`__radd__`）一次机会。
- **`__del__`** 的触发时机：`del obj`、作用域结束、GC 回收——**不适合做资源释放的可靠保证**（循环引用下的回收不确定）。

#### 6.5 三大特性
- **封装**：`_x` 约定私有，`__x` 名称改写为 `_类名__x`；`@property` 用方法包装属性读写；`__slots__` 限制属性、省内存。
- **继承**：`class Sub(Base):`；`super()` 按 MRO（C3 线性化）调用父类；`__bases__` 是直接父类元组；抽象基类用 `abc` 强制子类实现。
- **多态**：同一方法名不同实现，调用时按**运行时类型**分派；鸭子类型（只要接口一致即可）；魔法方法本质就是"多态的特例"。

#### 6.6 三种方法
| 类型 | 装饰器 | 首参 | 能访问 | 用途 |
|---|---|---|---|---|
| 实例方法 | 无 | `self` | 实例 + 类 | 对象行为 |
| 类方法 | `@classmethod` | `cls` | 仅类 | 工厂构造、类状态 |
| 静态方法 | `@staticmethod` | 无 | 均无 | 类内工具函数 |

### 7. Python —— 类型注解

- **注解是"提示"而非"约束"**：Python 不报错，仅 IDE/静态检查器（mypy、Pylance）层面告警。
- **语法**：`var: type = value`、`def f(x: T) -> R:`、`list[T]`、`dict[K, V]`、`tuple[T1, T2, ...]`。
- **元组特殊规则**：`tuple[int, str]` 按下标注释；`tuple[int, ...]` 表示"`int` 重复任意次"；`...` 只能出现在最后一个位置且只能用一次。
- **多类型**：`A | B` 或 `Union[A, B]`；**不固定用 `Any`**（关闭检查）。
- **`*args: int`** → 每个元素都是 int；**`**kwargs: int`** → 每个值都是 int（键永远 str）。

## 二、踩坑记录分析（现象 → 根因 → 解法）

> 以下坑全部来自你代码与笔记中的真实案例，按主题分组。**根因一栏尽量指向"语言规则的源头"，而非"错在哪一行"——这才是复盘的价值。**

### A. 类型与转换类

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| A1 | `int('3.14')` 报 `ValueError` | `int()` 只接受"整数字符串"或数字；"小数形式的字符串"符合 `int` 参数类型但**语义不合法**——这正是 `ValueError`（值错）与 `TypeError`（型错）的经典区分场景 | 先 `float()` 后 `int()`：`int(float('3.14'))` |
| A2 | `f"{result:.2f}"` 对字符串报 `ValueError`（或等效格式错误） | `:.2f` 是**数值格式化**，作用于 str 时把 str 当成数字解析；但你又说"字符串不能 :.f"——本质是 `float` 与 `str` 格式化协议不同 | 表达式返回 str 时，先 `float(...)`，或跳过 `:.2f` 用普通拼接 |
| A3 | `bool(0.0)`、`bool([])`、`bool(None)` 全为 `False` | **Python 的"真值测试"** 走 `__bool__` / `__len__` 协议：`0 / 空容器 / None` 皆假 | 判断"有无内容"时直接用 `if obj:` 而非 `if obj is not None:` |
| A4 | `input()` 拿到的 `"50"` 参与加法得 `"5010"` | `input` 恒返回 str，Python **无隐式转换** | 立即 `float()/int()`；最好封装"输入即校验"函数（你后期做到了 `get_float`） |
| A5 | 浮点运算 `0.1+0.2=0.30000000000000004` | IEEE 754 二进制无法精确表示部分十进制小数 | 用 `round()` 或 `decimal.Decimal`；对比用 `abs(a-b) < 1e-9` |
| A6 | `f"{a}...{result:.2f}"` 报错 | 同上：`result` 已是 str，`:f` 应用于错误类型 | 先转换再格式化 |

### B. 容器类

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| B1 | `(100)` 不是元组，是 int | `()` 只在**包含逗号时**才是元组构造；`(expr)` 是括号表达式 | 单元素元组写 `(100,)` |
| B2 | `{}` 想建空集合，得空字典 | `{}` 是 dict 字面量的语法糖，**空集合无字面量** | `set()` |
| B3 | 字典 `.values()` 返回的"视图"不能下标 `v[0]` | `keys/values/items` 返回的是**动态视图**，只支持迭代与 `in`，不可索引 | `list(d.values())[0]` 或直接迭代 |
| B4 | `del list_obj[0]` 有效，`del str_obj[0]` 报错 | `del` 只能删"**可变序列**"的元素；str/tuple 不可变 | 需要新串就切片重建：`s = s[:i]+s[i+1:]` |
| B5 | 遍历 list 中 `list.remove(x)`，删除不彻底 | 边遍历边删，索引与长度错位，**缩容后跳过元素** | 用 `while x in lst: lst.remove(x)`，或列表推导式重建，或倒序遍历 |
| B6 | `dict.fromkeys(keys, [])` 后修改一个键的空列表，**所有键都变** | `fromkeys` 默认值**被所有键共享同一个对象引用** | 用 `{k: [] for k in keys}`，或 `fromkeys(keys, None)` 再逐个赋新容器 |
| B7 | `d.popitem()` 删掉的元素"随机" | 3.7+ 才固定为 LIFO（删最后一个）；3.6 及以前无序 | 明确版本；需要删指定键用 `pop(k)` |
| B8 | `x in lst` 判断 5 不在 `["5"]` 中，以为是 bug | `int 5` 与 `str "5"` 值不同、类型不同，**不做隐式转换** | 统一类型后再比，或显式 `any(str(v)=="5" for v in lst)` |
| B9 | 列表推导式去重 `[x for x in lst if x not in ...]` 逻辑混乱、顺序丢失 | 列表推导式**不擅长"需要看历史"的去重**，且体积 O(n²) | 保持顺序去重用 `list(dict.fromkeys(lst))`；不保序用 `list(set(lst))` |
| B10 | 切片取值越界不报错，切片赋值越界却报 `IndexError` | 取值操作"裁到边界内"是设计；赋值要"插入元素"却无合法插入点 | 先 `len` 校验，或用 `if idx < len` 守卫 |

### C. 函数与作用域类

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| C1 | 函数内部 `x = 20` 后，外部 `x` 没变 | 函数内**赋值即声明**，新建了局部 `x`，遮蔽全局 | 需修改全局时 `global x`；嵌套写外层用 `nonlocal x` |
| C2 | 先调用后定义报 `NameError` | Python 是**运行时解析**，`def` 语句执行后函数名才存在 | 先定义再调用；或用"函数体内互相调用"（此时调用发生在定义完成后） |
| C3 | `def f(a=[]): a.append(1)` 第二次调用 `a` 已非空 | **默认参数在 `def` 执行时求值一次**，可变对象成为"单例" | 默认值用 `None`，函数体内 `if a is None: a = []` |
| C4 | `filter/map` 结果打印出 `<filter object at ...>` | 返回**迭代器**而非容器 | `list(filter(...))` 或直接 `for` 消费 |
| C5 | `lambda x: x["score"] + 5` 后想 `s["name"]` 报错 | `map` 里 lambda 返回的是"数值"，`s` 已是数字，不能下标 | 返回结构化新 dict：`lambda x: {**x, "score": x["score"]+5}` |
| C6 | 生成器表达式被 `sum` 消费后再遍历为空 | 生成器**一次性消费** | 需要复用就 `list(gen)` 物化一次 |
| C7 | `sum(x for x in word if x in "aeiou")` 之类写法的 `sum()` 报 `TypeError` | `sum` 只能加**数字**；若 `x` 是字符则错 | 用 `sum(1 for ...)` 或用 `len([...])` |
| C8 | 变量名 `count` / `max` / `sum` 与内建函数冲突，函数内 `count(...)` 报 `'int' object is not callable` | **遮蔽内建**：把内建名拿来当变量名 | 变量名加语义前缀（`score_count`、`max_score`），或 `builtins.sum` 兜底 |

### D. 异常处理类

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| D1 | 裸 `except:` 后按 `Ctrl+C` 程序"卡住"不退 | 裸 `except` 捕获 `BaseException` 全家（含 `KeyboardInterrupt`） | 显式 `except ValueError:` 或至少 `except Exception:` |
| D2 | `try` 块内写错语法，`except` 抓不到 | `SyntaxError` 在**编译期**抛出，`try` 运行时才开始生效 | 语法问题只能改代码；`try` 只放"运行期可能出错的几行" |
| D3 | 函数内 `raise ValueError("年龄不能为负")` 直接崩程序 | 该异常没有外层 `try` 接住 → 沿调用栈上抛 | 需要"就近兜底"就在调用处 `try`；需要"显式失败"就让它崩（这正是其设计意图） |
| D4 | `except` 内 `try` 已执行 `raise TypeError(...) from e` 后整个程序终止 | 在 `except` 块内抛新异常，**外层无捕获**，等价于 raise 到顶 | 要么再包一层 `try`，要么承认"这层就该终止" |
| D5 | `finally` 内 `return` 后错误信息莫名"消失" | `return` 会**覆盖正在传播的异常**（"吞异常"） | `finally` 只做清理（`close()` 等），绝不 `return` |
| D6 | `int('abc')` 明明想"抛 ValueError 让调用者处理"，却在 `except` 里把错误吞了转成 `print` + `return None` | 混合了"错误提示"与"错误返回值"两种责任 | 要么返回值（`None`/`False`），要么抛异常；不要两套并存。**你后期逐步转向"函数返回三态 `True/False/None`"是正确方向** |

### E. 文件与 IO 类

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| E1 | 读到 `UnicodeDecodeError: 'gbk' codec can't decode ...` | `open` 不写 `encoding` 时用**操作系统默认解码器**（Windows=GBK）；文件本身是 UTF-8 | 永远显式 `encoding="utf-8"` |
| E2 | `w` 模式打开后 `read()` 得到 `''` | `w` 打开就**清空了文件**，光标在开头但内容已无 | `w+` 想立刻读回需先 `write` 后 `seek(0)`；**读写分离才是正确姿势** |
| E3 | `r+` 写完再读，读不到刚写的内容 | 写后光标停留在写结束处 | `f.seek(0)` 后 `read()` |
| E4 | `a` 模式打开后 `read()` 得到空 | 光标在末尾 | `seek(0)` 再读（但语义仍反直觉，推荐读写分开） |
| E5 | `writelines(['a','b'])` 后两行粘一起 | `writelines` **不自动补换行** | 每行自备 `"\n"`，或 `"\n".join(lines)` 后 `write` |
| E6 | `readline()` 到末尾返回 `''` 而非 `None`，`if line is None` 死循环 | `readline` 读到 EOF 返回**空字符串** | 用 `if not line: break` 或 `for line in f:`（推荐，内存友好） |
| E7 | `open('x.txt', mode=123)` 报 `TypeError` | mode 必须是 str，参数类型不匹配 → `TypeError`；若 mode 是合法 str 但取值非法（如 `'x'`）→ `ValueError` | 记住 "**型错 TypeError / 值错 ValueError**" |
| E8 | `seek()` 在文本模式下移动到"半个汉字"处乱码 | 文本模式坐标是"字节"，中文多字节 | 文本模式只用 `seek(0)` / `seek(0,2)`；精确移动用二进制模式 |
| E9 | 用绝对路径读取，上传 GitHub / 移动目录后 404 | 绝对路径依赖"本地盘符"，**可移植性差** | 一律使用**相对路径**（与当前脚本同一基目录），或 `pathlib.Path(__file__).parent / "data.txt"` |

### F. 模块与包类

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| F1 | `import` 自己的模块报 `ModuleNotFoundError` | `sys.path[0]` 是"脚本所在目录"，跨目录导入默认找不到 | `import sys; sys.path.append(包的父目录)`，或在 IDE 中设 Source Root，或配 `PYTHONPATH` 环境变量 |
| F2 | VSCode 能跑，IDLE 报错；或反之 | 不同 IDE 对 `sys.path` 的注入策略不同 | 认知上明确"**sys.path 是运行时上下文，IDE 只是模拟**"；真正的工程化方案是用 `pyproject.toml` / 可安装包 |
| F3 | 文件名带 `-` 的模块无法 import | `import` 语法只接受**合法标识符**（不能用 `-`） | 文件名用下划线：`my-utils.py` → `my_utils.py` |
| F4 | 父文件夹含中文，导致模块与方法显示异常 / 警告 | `sys.path` 中的路径编码问题、部分工具链对非 ASCII 路径支持差 | 项目根目录避免中文；必要时删除 `.idea` 重建、重配解释器 |
| F5 | 自己写了 `random_test.py`，`import random` 导入了自己 | **自定义模块与标准库同名时，`sys.path[0]` 优先，覆盖标准库** | 自定义模块加前缀防冲突；理解"查找顺序"比记规则重要 |
| F6 | `from m import *` 后变量莫名被覆盖 | 通配符导入污染全局命名空间，且不报冲突 | 用 `import m` 或 `from m import 具体名`；在被导入模块用 `__all__` 限定 |
| F7 | `pip install` 的包在别的项目"找不到"，或引用了错误的 CPU/版本 | 未使用虚拟环境，包装进了全局环境或错误的解释器 | `python -m venv venv` → 激活 → `pip install`；用 `pip show 包名` 的 `Location` 字段验证"是否装进 venv" |

### G. 面向对象类

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| G1 | `obj.类属性 = 值` 后"以为改了类属性"，实际只影响本实例 | 赋值在 `obj.__dict__` 上**新建**同名键，类 `__dict__` 未动 | 需要改类属性就 `类名.属性 = 值`；需要"每个实例独立"就在 `__init__` 里 `self.x = ...` |
| G2 | 打印对象是 `<__main__.X object at 0x...>` | 默认继承 `object.__str__`/`__repr__`，返回内存地址 | 覆盖 `__str__`（人看）/`__repr__`（开发者看）；两者都只返回 str |
| G3 | `__add__` 遇到非本类型 `return NotImplementedError` 导致直接崩溃 | `NotImplementedError` 是"已实现但故意未实现"的信号异常，**不是"类型不匹配"的信号** | 返回 **`NotImplemented`**（一个特殊单例值），给反向方法 `__radd__` 机会 |
| G4 | 链式 `a + b + c` 中 `b` 的中间结果"找不到" | Python 计算后产生**临时对象**，无引用即 GC | 这就是 `__del__` 打印"中间对象已销毁"的来源——正常现象，别误以为 bug |
| G5 | `def __del__` 里做"必须执行的清理"，有时不执行 | 循环引用下 GC 的回收时机不确定，且解释器退出时属性可能已部分销毁 | 用 `with` 上下文管理器（`__enter__`/`__exit__`）承载资源释放 |
| G6 | 在类外 `obj.add = 123` 把方法"变成"属性，之后 `obj.add()` 报 `'int' object is not callable` | 实例 `__dict__` 可以覆盖类方法名 | 类型约定；或 `__slots__` 限制动态挂载属性（`__slots__` 只能禁用**新增**，已存在方法名仍可被遮蔽） |
| G7 | 实例属性与类属性同名，`obj.x` 到底取哪个 | 查找链：实例 `__dict__` 优先 → 类 `__dict__` | 明确定义：**"该属性每个对象都相同（如学校名）→ 类属性；每个对象各不同（如姓名）→ 实例属性"** |

### H. 逻辑与算法类

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| H1 | 二次函数求根中 `round(-b/(2*a))` 不带精度，与另一分支 `round(...,2)` 不一致 | 精度参数遗漏，代码不一致 | 统一封装一个 `round(x, 2)` 的辅助，或集中精度常量 |
| H2 | 学生管理 `count_max_min_avg` 里 `for name, score in students.items()` 与外层 `for subj, score in cls_subjects_score.items()` 用同名 `score` 遮蔽 | 变量名过短、语义重复 | 命名区分：`scores_by_subject` vs `student_scores`；作用域很短的循环也应语义化 |
| H3 | `while start % n != 0: start += 1` 中 `start` 已满足（`100 % 3 != 0`）能正常推进，但若 `start` 是负数或 `n == 0` 会死循环 / 除零 | 边界缺失 | `n > 0` 前提检查；用 `start += (-start) % n` 一步到位（数学技巧） |
| H4 | 递归 `factorial(n)` 未判 `n <= 1` 时，`n==0` 也能返回 1 但不符合 `0!` 的直觉；`n` 为负会无限递归 | 终止条件覆盖不全 | 终止条件要覆盖**所有非递归分支**：`if n <= 1: return 1` |
| H5 | 阶乘用**递归**计算 `factorial(50)` 结果"看起来不对" | Python int 精度是无限的（不会溢出，会非常长）；`float` 才有精度问题；嵌套深度也可能爆 | 大数用 int；超过 1000 层用迭代或 `sys.setrecursionlimit` |
| H6 | `students = [{...}]` 中所有人成绩都是 90 才能进入"优秀"分支 | 边界漏了"空输入"、"等于 90 是否算优秀" | 明确">= 与 >"，先判空再判分 |
| H7 | `range(1, True)` 一次都不循环 | `True == 1`（bool 是 int 子类），`range(1, 1)` 是空区间 | 写 `range(1, n+1)`，别拿 bool 当边界值 |
| H8 | 素数筛 `for j in range(2, i)` 效率低、且 `i=2` 时 `range(2,2)` 空→ `is_prime=True` 恰好正确 | 靠"空区间"正确是偶然 | 用 `range(2, int(i**0.5)+1)` 并显式 `i < 2: return False` |
| H9 | 菱形打印 `2*min(i, n-1-i)+1` 思路正确，但**步长/空格**需与 `width/height/center` 对齐 | 字符宽度（中文占 2 列）与"字符数"混用 | 统一按"视觉列数"计算；中英文混排需 `wcwidth` 或统一用 ASCII 画图 |
| H10 | `diamond(15)` 中 `n` 为偶数时会被错误处理（你写了"n 必须为奇数"） | 菱形对称中心需要"奇数列" | 在入口 `n = n if n%2 else n+1`，或先断言 |

### I. 工程与环境类

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| I1 | 全局装的库在 venv 里 `pip list` 看不到，反之亦然 | 全局解释器与 venv 解释器是**两套 site-packages** | `where python` 确认解释器；`pip show` 的 `Location` 确认装到哪；IDE 中"Select Interpreter"指向 venv |

| I4 | 相对路径在某些调用方式下找不到文件 | 相对路径的基准是"**进程工作目录（cwd）**"，而非"脚本文件目录" | `Path(__file__).parent` 显式定位；或 `os.chdir(os.path.dirname(__file__))` |

### C. 你现在最该补的五件事（按 ROI 排序）

1. **命名规范统一**（最低成本，最高回报）
   - 变量/函数：`snake_case`；类：`PascalCase`；常量：`CONSTANT_CASE`。
   - **禁止中英混用**（`学生系统` / `Stuents` 拼写错误 / `Clss01`）；同样含义全项目一个名字。
   - **禁止遮蔽内建**：`list` / `dict` / `max` / `min` / `sum` / `count` / `type` / `id` / `input` / `next`。

2. **用"数据类"替代"字典建模"**
   - 你已经用 `class Shopping`、`class Student` 存数据，思路正确。
   - 但 `self.OS = {name: {subject: score}}` 可以升级为 `@dataclass`（Python 3.7+），自动生成 `__init__` / `__repr__` / `__eq__`，消除大量样板代码。

3. **建立"边界用例清单"作为开发前置**
   - 每个函数写之前先问：**空输入？0？负？超界？类型错？中文？** 六问。
   - 例：`add(name, price, qty)` 的边界清单：`price=0` / `qty=-1` / `qty=1.5` / `name=""`（重名？）/ `name` 超长。

4. **区分"合法值域"与"数学恒正"**
   - 现在的 `abs(float(x))` 到处出现，实际上是"**用数学手段悄悄掩盖输入错误**"。
   - 年龄不该允许 `-5` 变成 `5`，成绩 `-50` 也不该变 `50`（教务系统那题老师直接 `float()` 让负数通过，也是漏洞）。
   - **正确姿势**：业务上不允许就直接拒绝并提示；只有"物理量取绝对值"（如半径、边长）才用 `abs`。

5. **拥抱 Pythonic：用"内建 + 迭代协议"替代手写循环**
   - `for i in range(len(lst))` → `enumerate(lst)` 或直接 `for x in lst`；
   - `max/min/sum/any/all` / `zip` / `dict` 推导 `/` 生成器表达式——你已经部分使用，可以进一步普及；
   - **`pathlib` 替代 `os.path`**，**`f-string` 替代 `%`/`format`**（你已基本做到）。
